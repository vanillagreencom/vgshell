# Hyprland layer

Covers: shell/Core/HyprlandLayer.qml, shell/Core/HyprlandLayer.js, shell/Core/Pads.js, scripts/smoke/rows/scratchpads.sh, shell/Core/Notices.qml, shell/Hosts/NoticeHost.qml, bin/vgshell-hypr-judge, scripts/test-hyprland-layer.js, scripts/test-vgshell-hypr.sh, scripts/smoke/rows/hyprland-consent.sh, scripts/smoke/rows/hyprland-consent-decline.sh, scripts/smoke/rows/hyprland.sh, scripts/smoke/rows/windows.sh, scripts/smoke/toplevel/toplevel.c

Hyprland is configured in Lua alone; a classic `hyprland.conf` is unsupported. The shell writes one Lua file, the Hyprland layer, to `${XDG_STATE_HOME:-~/.local/state}/vgshell/hypr/vgs.lua`, and one line in the user's `hyprland.lua` loads it. No plugin writes Hyprland configuration: a plugin declares its keys, blur rules, theme appearance switches and input options as data in its manifest, and the core renders them. The core adds constant sections of its own: the floating TUIs' window rules, the shell's application window rule, the overlay keyboard capture, the key capture pass-through and the session lock's restore. [D028](../decisions/D028-one-generated-hyprland-layer.md) records the layer, [D044](../decisions/D044-application-windows-are-hyprland-toplevels.md) records application windows, and [D048](../decisions/D048-theme-owned-hyprland-appearance.md) records the theme-owned appearance groups.

## The file

`HyprlandLayer.js` renders the text, and `PluginLogic.hyprlandSection` gives it each plugin's part. In order:

1. A header saying the file is generated and naming `vgshell hypr render`, which writes it again.
2. One Theme appearance section for each enabled group, in fixed order: `borders`, `radius`, `motion`, `noGaps`. A disabled group writes only a comment and no `hl.*` call.
3. The floating TUIs' window rules, one `hl.window_rule` per size class, headed `-- Floating TUIs: each size class's app-id floats, centred, at its size, clamped to its output.` `HyprlandLayer.TUI_WINDOWS` holds each class's app-id, rule name and preferred size, and the class pattern is the app-id anchored with each dot escaped, so the two cannot differ. Each size is two Hyprland expressions, `"min(<width>,monitor_w-<2 × gutter>)"` and `"min(<height>,monitor_h-<bar + 2 × gutter>)"`, from `Theme.size.window.gutter` and `Theme.bar.height`, which Hyprland evaluates against the monitor's logical size when the window maps ([runtime-hyprland.md](runtime-hyprland.md)). Hyprland has no reserved-area variable, so the bar's height is subtracted whether or not the monitor has a bar. The section is written whatever the plugins, no plugin text reaches it, and it changes only with those two tokens.
4. The shell's application window rule, one `hl.window_rule` named `vgs:window`, headed `-- Application windows: the shell's windows float, centred, at the size they ask.` It matches the class `HyprlandLayer.APP_WINDOW.appId`, `org.vgs.shell`, the app-id the `//@ pragma AppId` line of `shell.qml` gives every window the shell maps, and floats and centres it with no size. The section is constant.
5. The overlay keyboard capture section, headed `-- Overlay keyboard capture: full-screen vgs overlays own keys through a submap.` It defines the `vgs:capture` submap, repeats enabled plugin binds inside it, wraps `hl.dsp.focus` and `hl.bind` once to learn default-map directional focus binds, and enters or leaves the submap from `layer.opened`, `layer.closed` and `config.reloaded` by reading `hl.get_layers()`. [D067](../decisions/D067-overlay-keyboard-capture.md) records the choice.
6. The key capture pass-through, headed `-- Key capture pass-through: a vgs window that captures a key combo takes every key but Escape.` The section is constant: [hyprland-shortcuts.md § Key capture pass-through](hyprland-shortcuts.md#key-capture-pass-through).
7. The session lock's restore, `hl.config({ misc = { allow_session_lock_restore = true } })`, headed `-- Session lock: a restarted shell takes over a lock whose client died.` What it allows and why is [lock-polkit.md § Lock](lock-polkit.md#lock). The section is constant.
8. One section per enabled plugin whose manifest declares `hyprland` binds or layer rules, by plugin id, headed `-- <id> <version>: binds and layer rules from its manifest`. Its layer rules come first, each named `<id>:<name>` for namespace `^vgs:<name>$`, then its binds, each `hl.dsp.global("<id>:<shortcut>")` with that shortcut id as its description. A plugin whose `plugins` row sets one of its `hyprland.options` has an options section just before it, written only for the options the row sets: [hyprland-options.md](hyprland-options.md). The first enabled section by id whose manifest declares `hyprland.pads` ends with its pads, headed `-- <id> <version>: pads from its manifest`; a later one's are the comment `-- pads of <id> skipped: <owner> defines them`, reported among that plugin's problems.
9. The pads' sweep, headed `-- Pads: a window in a pad's workspace that no pad holds comes to the focused workspace.`: as the file loads, each window in a `special:vgs-pad-<name>` workspace whose pad `hl.__vgs_pads` does not hold, as after the pad's removal or its plugin's disabling, moves to the focused workspace. The section is constant.

- **Theme appearance.** `borders` writes the border colours `HyprlandLayer.BORDERS` maps, `general.border_size` and `decoration.shadow.color`. `radius` writes `decoration.rounding`, `decoration.rounding_power`, `group.groupbar.rounding` and `group.groupbar.gradient_rounding`. Group tabs use the window radius times the highest monitor scale, bounded to 20, because Hyprland scales window corners per monitor but not tab rounding. `HyprlandLayer.qml` gets each screen from `Quickshell.screens` and maps it to a Hyprland monitor through `Hyprland.monitorFor(screen)`; the Quickshell 0.3.1 reference states that `Quickshell.screens` lists `ShellScreen` objects and `Hyprland.monitorFor(screen)` returns the corresponding `HyprlandMonitor`. It falls back to `ShellScreen.devicePixelRatio`, and an unknown scale counts as 1. `motion` writes one core preset for window, layer, workspace and fade leaves. It never writes `global` or `border`. `noGaps` writes `hl.workspace_rule({ workspace = "", gaps_in = 0, gaps_out = 0 })` for every workspace, which a user's `general` gaps after the loading line do not undo ([runtime-hyprland.md](runtime-hyprland.md#workspace-rules)). Themes carry no gaps, so a theme apply leaves it as it is; off, the layer writes no gaps.
- **Appearance switches.** A plugin declares `hyprland.appearance` as a map from `borders`, `radius`, `motion` or `noGaps` to one of its boolean schema keys. The first enabled declaration by plugin id owns the switches. Later declarations are reported as `hyprland: appearance declaration ignored for <id>: already owned by <owner>`. With no owner, borders and radius are on and motion and no gaps are off. The `vgs.themes` defaults use those same values.

- **Floating TUIs.** A floating TUI's terminal opens with the app-id of its size class, and that class's rule floats the window, centres it on its monitor's work area and gives it the class's preferred size, clamped to the output. No plugin sets a size or a class pattern. [D028's revisit outcome](../decisions/D028-one-generated-hyprland-layer.md#revisit-outcome-2026-09-28-vgs-513) compares the rules with Omarchy's floating windows.

  | Size class | App-id | Rule | Preferred size, clamped to the output less `size.window.gutter` a side and the bar's height |
  |---|---|---|---|
  | `default` | `org.vgs.tui` | `vgs:tui` | 875 × 600 |
  | `wide` | `org.vgs.tui.wide` | `vgs:tui-wide` | 1200 × 720 |
  | `tall` | `org.vgs.tui.tall` | `vgs:tui-tall` | 875 × 900 |

- **Application windows.** A window of kind `window` ([surfaces.md](surfaces.md)) has the shell's class and its plugin's name as its title. `vgs:window` floats it and centres it on its monitor's work area, and it keeps the size it asks for. A user rule matches one window by the class and the title.
- **Pads.** `HyprlandLayer.padLines` writes `hl.__vgs_pads` (`HyprlandLayer.PADS`): a table of each pad's judged values ([plugin-manifest.md § Pads](plugin-manifest.md#pads)), one window rule `<id>:pad-<name>` per pad that maps a window of its class into `special:vgs-pad-<name>` hidden, tiled and unfocused, and `toggle(name, screen)`, which `Dispatch.padRequest` calls and the `compositor` capability's `togglePad` sends. In one Lua call `toggle` hides a shown pad and gives the focus back to the window that had it while that window is on a shown workspace, or refuses with the error `vgs-pad=<key>` of `HyprlandLayer.PADS.answers`: a pad the table does not hold, a pad whose workspace holds no window, a screen Hyprland does not list; otherwise it moves the workspace to the screen, the focused one for `""`, writes its `gaps_out` from the pad's shares of that monitor's work area, sets `specialWorkspaceIn` and `specialWorkspaceOut` to the pad's motion and entry side, shows it and focuses its window. A `window.active` hook hides a shown pad once the focus moves to a window outside it, and each shown pad is fitted again on `monitor.layout_changed` and each time the layer runs. The pads move on the curve and speed of the theme's motion preset's `workspaces` leaf, scaled by its motion scale, and not at all under a scale of 0 or the `none` preset. The facts are in [runtime-hyprland-pads.md](runtime-hyprland-pads.md); [D102](../decisions/D102-pads-tiled-in-their-special-workspace.md) records the choice.
- **Keys.** [hyprland-shortcuts.md](hyprland-shortcuts.md) defines key normalization, configuration overrides, effective key reads and hold release binds.
- **Conflicts.** A key two binds claim stays with the first plugin by id. The later bind is written as `-- skipped <key>: already bound by <id>`. A layer rule an earlier section wrote, with the same namespace and effects, is written once and noted.
- **Reports.** `vgshell plugin list` and the `listPlugins` IPC list each skipped bind, each refused pad, each plugin whose pads another defines, each `keys` name no bind declares, each ignored appearance owner, each skipped or refused option, and a failed write, mkdir or reload among their errors, each led by `hyprland: `. `HyprlandLayer.qml` hands them to the registry, which both read, and the Settings window shows a plugin's own among its errors.
- **Overlay capture.** A full-screen overlay has namespace `vgs:overlay`. While one is mapped, Hyprland stays in `vgs:capture`. Unbound keys go to the overlay because the host gives it exclusive keyboard focus. The capture submap repeats every enabled plugin shortcut and learns user directional focus binds from dispatcher objects as `hl.bind` receives them.
- **Key capture pass-through.** [hyprland-shortcuts.md § Key capture pass-through](hyprland-shortcuts.md#key-capture-pass-through) defines when the shell and the layer enter and leave `vgs:passthrough`.
- **Plugin text.** The only plugin text in the file is data a judge has checked. The manifest judge checks the id, shortcut names, keys, namespaces, option setting names, booleans, numbers and option strings. The option setting name must be a setting name. An option string must match the character set in [hyprland-options.md](hyprland-options.md). A version, theme name, setting name or refusal reason reaches a comment only after every character outside printable ASCII is replaced by `?`, so a line break cannot start Lua.

## When the shell writes it

`HyprlandLayer.qml` runs in the runner's shell only. It renders once the first scan is done, the configuration is ready and the theme file is read, and again whenever the plugins, `shell.json`, enablement or the theme change. A theme apply writes `theme.json`, so it reaches the layer too. The shell writes the file by rename, only when its bytes change, then runs `hyprctl reload config-only`. `vgshell hypr render`, the `renderHyprland` IPC, reads the file again, then writes it and reloads Hyprland whatever the bytes; a request made while a step runs starts its own cycle once that step ends.

`HyprlandLayer.step` decides each step, and the QML runs it. Quickshell's `FileView` writes nothing for the bytes it last read or wrote, and keeps a failed write's bytes as those, so after a failed write the next cycle reads the file first. A text whose directory or write failed is written again only once the text changes or a render asks for it, so an unwritable directory costs one attempt per change.

## Invariants

1. The manifest's `hyprland` key, a key's form, a row's `keys`, `hyprland.appearance` and each plugin's binds are decided in `PluginLogic.js`; the text, its order, the appearance owner, the conflicts, the one copy of a shared rule and the writer's sequence are decided in `HyprlandLayer.js`. Enforced by `scripts/test-hyprland-layer.js`, whose controls each remove one rule from a copy of one of the two files; its step rows include a failed write followed by the same text and then a new one, and a render asked during a reload after the file was removed.
2. The floating TUIs' window rules are written byte for byte as § The file gives them, after the Theme appearance sections and before the first plugin section, with or without plugin sections, and a missing, negative or non-finite margin is refused by name. Enforced by the same suite, which pins the text and its place; its controls drop the section, write it before Theme appearance, leave the dots in the class pattern unescaped, leave the pattern unanchored, drop the gutter from the width, drop the bar from the height, write fixed sizes and accept a negative margin.
3. No plugin text reaches the layer's Lua but the judged data above, and a comment holds printable ASCII alone. Enforced by the same suite's manifest rows and its comment row.
4. A full-screen overlay enters `vgs:capture`, keeps enabled plugin binds live there, learns default-map directional focus binds and resets only its own submap. Enforced by `scripts/test-hyprland-layer.js`, `scripts/smoke/rows/theme-browser.sh` and `scripts/smoke/rows/overlay-capture.sh`, with controls that remove submap entry, plugin bind copy, the focus wrapper and layer-close reset.
5. The consent and line wiring rules are in [hyprland-wiring.md](hyprland-wiring.md#invariants).
6. On the nested instance the consent row wires the harness's `hyprland.lua`; then enabled plugins' binds and rules are loaded, and `SUPER+SPACE` and `SUPER+N` typed on the seat open the launcher and the inbox. A `keys` rebind, an unbind and a conflict reach Hyprland and `listPlugins`, a disabled plugin's section goes, the active border follows a theme apply, `render` writes a removed file again, `unwire` unloads the binds, and `configerrors` stays empty. The same row applies a fixture theme whose Hyprland border is 4 and radius is 8, turns the switches off and reads the compositor values back, then turns motion on and reads animations. Enforced by `scripts/smoke/rows/hyprland.sh`, which fails on a shell copy that writes the layer and never reloads Hyprland.
7. On the nested instance Hyprland v0.56.2 accepts the floating TUIs' rules with an empty `configerrors`. A window of each class, which the harness's toplevel helper maps, floats at its preferred size clamped to the output, inside and centred on its monitor's work area, at the sandbox's own mode, at 3008 × 1692, where each class takes its preferred size exactly, and at 1440 × 900, where a control reads that the tall class's preferred box leaves the work area. The helper exits 0 when the row stops it by its pid. After `hl.window_rule({ name = "vgs:tui", enabled = false })` below the line, an `org.vgs.tui` window tiles and an `org.vgs.tui.wide` window still floats. Enforced by `scripts/smoke/rows/hyprland.sh`. It failed on 2026-09-28 on a shell copy whose layer drops the section (no class floats or takes its size) and on one that names the default rule `vgs:tui-default` (the override leaves `org.vgs.tui` floating). No layer edit fails the centre row alone: v0.56.2 centres a new floating window that asks no position on the work area with or without `center` ([runtime-hyprland.md](runtime-hyprland.md)), read on a shell copy whose rules drop `center = true`.
8. On the nested instance the Settings window, of the shell's class, floats and is centred on its monitor's work area, and after `hl.window_rule({ name = "vgs:window", enabled = false })` below the line it tiles. Enforced by `scripts/smoke/rows/windows.sh`. `scripts/test-hyprland-layer.js` pins the rule byte for byte after the floating TUIs' rules and holds `shell.qml`'s AppId pragma equal to its class; its controls drop the rule, write it before the TUIs' rules, match `org.quickshell`, and drop, change or misplace the pragma.
9. The session lock's restore is written byte for byte after the key capture pass-through section, before any plugin section, and Hyprland v0.56.2 reads `misc:allow_session_lock_restore` back as true. Enforced by `scripts/test-hyprland-layer.js`, whose controls drop the section and turn the option off, and by `scripts/smoke/rows/lock.sh`, which reads the option and takes over a lock a killed shell left.
10. The input options and the `hyprland` capability's rules are in [hyprland-options.md](hyprland-options.md#invariants).
11. The layer holds no `hl.monitor` line: VGS writes no monitor rule ([D096](../decisions/D096-vgs-reads-outputs-and-writes-no-monitor-rule.md)). The checks that hold it are in [hyprland-monitors.md](hyprland-monitors.md#invariants).
12. The key capture pass-through's rules are in [hyprland-shortcuts.md](hyprland-shortcuts.md#key-capture-pass-through).
13. `noGaps` is written byte for byte after `motion` while on, and as a comment while off. Enforced by `scripts/test-hyprland-layer.js` with controls, and on the nested instance by `scripts/smoke/rows/style.sh`.
14. The pads are written byte for byte after their plugin's binds, by the first plugin by id alone, with their motion from the theme, a later plugin's reported, and the sweep ends every layer. Enforced by `scripts/test-hyprland-layer.js`, whose controls each remove one rule of the section or the sweep. On the nested instance a pad's key never shows an empty pad, shows it at its shares and anchor on the screen it names whatever monitor the pointer is on, at three modes, at scale 2 and after a mode change while shown, hides it and gives the keyboard back, as many toggles as presses; a focus move elsewhere and a press beside it hide it, and turning the plugin off or removing the pad brings its window to the focused workspace: `scripts/smoke/rows/scratchpads.sh`, whose controls read an empty pad, a background that takes no press, a layer with no gaps, and a layer with no focus hook, no refit and no focus given back.
