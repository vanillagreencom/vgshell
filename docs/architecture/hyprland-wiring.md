# Hyprland layer wiring

Covers: bin/vgshell-hypr-judge, bin/vgshell, shell/Core/HyprlandLayer.qml, shell/Core/PluginLogic.js, shell/Core/HyprlandLayer.js, shell/Core/Notices.qml, shell/Hosts/NoticeHost.qml, scripts/test-vgshell-hypr.sh, scripts/test-hyprland-layer.js, scripts/smoke/rows/hyprland-consent.sh, scripts/smoke/rows/hyprland-consent-decline.sh

The Hyprland layer is [hyprland.md](hyprland.md). This file holds the line that loads it and the consent question that may add that line.

## The line

`vgshell hypr state` reads `${XDG_CONFIG_HOME:-~/.config}/hypr/hyprland.lua` and prints whether the loading line is `wired`, `unwired` or `absent`. It changes nothing. `vgshell hypr wire` keeps `pcall(dofile, "<state dir>/hypr/vgs.lua")` in that file, first when it adds it. `vgshell hypr unwire` removes every copy. The three verbs follow the theme include line's rule, [theme-wiring.md § Wiring text](theme-wiring.md#wiring-text): a whole-line match, no other byte changed, a symlink resolved and its target replaced with its mode kept, and the file never created. A state directory holding a quote, a backslash or a line break is refused, since the line holds it in a Lua string.

After the first read and any needed layer write and reload in one shell run, the shell runs `vgshell hypr state`. A `wired` or `absent` answer does nothing. An `unwired` answer raises the core notice on the focused screen, inside the first-start welcome until the user has closed it once ([requirement-notice.md](requirement-notice.md)), unless `$XDG_RUNTIME_DIR/vgshell/hypr/consent-declined` holds the current `HYPRLAND_INSTANCE_SIGNATURE`. Connect runs `vgshell hypr wire` and then `hyprctl reload config-only`. Not now and Escape write that marker. It applies only to this Hyprland session, because systemd lingering can keep `XDG_RUNTIME_DIR` alive after logout. A failed probe raises no question and is reported as a Hyprland problem; a failed Connect keeps the question open and names the failure. The shell writes nothing under `~/.config/hypr/vgshell/` and uses no `require` module name, so files and modules the user keeps there are left alone.

The line is first, so a user's own line after it acts on what the layer made: `hl.unbind("<keys>")` with the keys spelt as the layer writes them, `hl.layer_rule({ name = "<id>:<name>", enabled = false })`, which Hyprland v0.56.2 applies to the rule of that name, and `hl.window_rule({ name = "vgs:tui", enabled = false })`, which v0.56.2 applies the same way to a floating TUI's rule: a window of that class then tiles, as the sandbox reads back, and the other two classes still float. `hl.window_rule({ name = "vgs:window", enabled = false })` tiles the shell's application windows the same way. A later `hl.config` value wins too, but for the values the layer applies after the whole configuration ([hyprland.md § The file](hyprland.md#the-file)): the appearance groups that are on and each input option a plugin setting sets. A key is better changed in `shell.json`, which needs no edit of Hyprland's files.

An appearance group that is on holds over the user's own lines for its values, wherever they are, and no user line needs removing: `borders` over `general.border_size`, the border colours and `decoration.shadow.color`; `radius` over `decoration.rounding`, `decoration.rounding_power`, `group.groupbar.rounding` and `group.groupbar.gradient_rounding`; `motion` over `animations.enabled` and the `hl.animation` rows for windows, layers, workspaces and fades. A user who keeps their own values turns the group's switch off, and the layer then writes none of them. No window gaps holds as a workspace rule, and only a later workspace rule that sets gaps overrides it. An input option holds the same way while a plugin setting sets it; once the plugin's row sets it no longer, the user's line applies again ([hyprland-options.md](hyprland-options.md)). VGS edits no line of the user's but its own loading line.

## Invariants

1. `state` never creates or edits `hyprland.lua`, and reads `wired` with the same whole-line rule as `wire`. `wire` never creates `hyprland.lua`, puts the line first, keeps a symlink and its target's mode, and refuses a state directory a Lua string cannot hold; `unwire` leaves the file byte for byte as it was. Enforced by `scripts/test-vgshell-hypr.sh` under a temporary HOME, with judge copies that create, skip the quoting refusal, wire on `unwire`, report every run as a change and report an unwired file as wired as its controls.
2. The shell asks before wiring an unwired `hyprland.lua`; Connect wires and reloads; Not now writes the current Hyprland signature to a runtime marker; a restart in the same Hyprland session suppresses the question; a marker from another Hyprland session is ignored; a failed probe raises no question; a failed wire keeps the question open; the first start asks inside the welcome and a later one asks the plain question. Enforced by `scripts/test-hyprland-layer.js`, `scripts/test-notice-logic.js`, `scripts/smoke/rows/hyprland-consent.sh` and `scripts/smoke/rows/hyprland-consent-decline.sh`, with controls that skip the probe, skip the marker check, skip the marker write, ignore a connect queued during a write and ignore a wire failure.
3. On the nested instance the consent row wires the harness's `hyprland.lua` and changes no other line. Enforced by `scripts/smoke/rows/hyprland-consent.sh`.
