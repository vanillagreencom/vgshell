# The Jarvis daemon, its brains and its actions

Read before touching the Jarvis service, its daemon, a child it starts, its wire, its records, the capture indicator, a brain or speech adapter, a provider row, the tool bridge, a tool executor, a Setup step, a voice key, the Jarvis session row, the bar widget or the console.

## The approach

`vgs.jarvis` is one service that owns one Node child whose lease is its closed stdin; every module reaches the shell only through that child's wire, and every process the daemon starts dies with it. One wire judge, `JarvisProtocol.accept`, owns every shape in both directions, and the daemon owns the generation identity the service carries back. `Session` is the sole admission judge: capture opens only after the shell has presented the indicator, a passive layer the service owns, and never from a component's existence, a status file or a pending request. Private records hold names, never values. A failure is a keyed `jarvis: <area>=<cause>` with no provider text, and readiness comes only from its one judge. Always mode's capture listens only for the wake word, in the daemon-owned local sidecar ([D102](../decisions/D102-always-mode-local-wake-word.md)). The choices are [D064](../decisions/D064-jarvis-child-lease.md), [D070](../decisions/D070-jarvis-action-policy.md) and [D072](../decisions/D072-coding-task-records-and-four-fact-state.md).

Every brain reaches the model and the tools by the same controlled route. A brain is a wire adapter, whose driver sends only through `WireBrain.js`, or a harness adapter, the vendor's unmodified program behind the tool bridge ([D079](../decisions/D079-brains-wire-and-harness-adapters.md)). One engine object per conversation owns the brain, the release grants and the heard prefix, and ends them all when the generation changes ([D089](../decisions/D089-jarvis-chained-engine-and-heard-prefix.md)). The daemon owns the local speech sidecar across conversations. Always mode listens for the wake word, and for one short follow-up window after Jarvis speaks a reply to a voice request. Every item leaves through release, then audit, then the one network door that [jarvis-outbound.md](jarvis-outbound.md) governs. An account's Verified comes only from one explicit inference request the user started, judged by the same release owner.

Every action, a brain's tool call and a harness program's own approval request alike, passes one policy gate and reports only what it read back. An executor registers only after its own readiness probe passes, and every call reaches it through one serial router, `shell/plugins/vgs.jarvis/backend/ToolRouter.js`, which owns the only confirmation identity ([D070](../decisions/D070-jarvis-action-policy.md)). A command that may already have acted reports `unknown`, never `failed`. A desktop change goes to the shell as a request, so `shell/Core/Dispatch.js` stays the one dispatch judge.

## Why

A pipe closes after a shell crash without QML teardown, where a parent-death signal alone misses a parent already dead. Linux clears the parent-death signal across fork and a process group misses a descendant that closed its pipes, so only the death of a namespace's init kills every descendant. The microphone owner must not outlive the indicator, so a sidecar is a leased child and never a service. A pending mute while the daemon is unavailable means mute on, because no toggle state exists. An audit that stored a value would hold the secret it exists to keep out.

A harness tool left on would bypass the policy gate, and vendor terms allow a subscription only through the unmodified program. A provider error body can echo content or credentials, so it is cancelled unread. A chained brain has no server item to truncate, and bytes written overstate what was heard, so the heard prefix travels as a separate labelled item and history is never rewritten. A login-status or model-list reply proves an account exists, not that it answers, so only generated text verifies it.

A model can pick an action from untrusted file, page or screen content, so no executor may hold a second policy table or a confirm method; a serial hold removes Jarvis's own path to its own confirm key. A path judged by string can be swapped between the judgement and the open, so the executor rejudges at execution and walks held descriptors. A dispatcher answers `ok` without acting, and an application may keep its window open to ask about unsaved work, so only a read-back proves an effect. Registration proves nothing about confinement, so a shell tool is offered only after a real kernel probe answers.

## Rules

### Process and wire

- Do end the child by closing its stdin; never add a systemd unit or a detached keeper. `scripts/test-jarvis-daemon.js` and `scripts/smoke/rows/jarvis.sh` pin it.
- Do start every daemon child through `setpriv --pdeathsig KILL` with a parent check, run audio children inside a PID namespace that dies with the daemon, and give each child an explicit environment with no key and no `VGSHELL_RUNNER_PID`. `scripts/test-jarvis-audio-daemon.js`, `scripts/test-jarvis-audio.js` and `scripts/test-jarvis-desktop-tools.js` pin each.
- Never fall back to a host process, a unit or a privilege prompt when user namespaces are refused; report an audio fault. Gap: no test refuses user namespaces.
- Do pick the local tier in `setup-local` from the machine's NVIDIA GPU memory, RAM and CPU threads against each tier's measured need, with no hand step. The Jarvis page's Local voice choice overrides the pick. With no argument the setup window installs the tier the setting names. A failed run keeps the setting; a cancelled (exit 130) or finished run writes the ready tier back (`SetupGate.tierAfterRun`). `scripts/test-jarvis-setup.py`, `scripts/test-jarvis-setup-gate.js` and `scripts/smoke/rows/jarvis-setup.sh` pin each.
- Do let the daemon own the local speech sidecar across conversations and close it on daemon teardown and for a local voice setup run. The window's `setup-local release` asks the shell (`local-setup begin`), which takes the ask from the run's launch on, since the core's `shell.tui.state` reads a run live before any record of it is listed, and the shell sends `local-setup` `{running: true}`; a daemon still starting is told once it is ready. The daemon then ends a live local conversation or check with `speech=local-setting-up` and closes the sidecar. It answers `{}` only once the sidecar has exited and released its shared hold on `local-setup.lock`. It starts no sidecar until `{running: false}` or a daemon restart, then starts it on the new publication. Never write under the plugin directory from a child. `scripts/test-jarvis-engine.js`, `scripts/test-jarvis-protocol.js`, `scripts/test-jarvis-local-speech.js`, `scripts/smoke/rows/jarvis-setup.sh` and `scripts/smoke/rows/read-only-prefix.sh` pin each.
- Do record a failed local voice setup in `local-setup-failed.json` in the Jarvis state folder, `{cause, tier, log}`, where `log` is `setup-local.log`, which holds the window's keyed lines, the children's error lines and the probe's output. `setup-local` writes it on every failed install, words every failure in its own plain line, and the next successful install removes it. The Voice step words it only for the tier the setting wants while that tier is not ready (`SetupGate.localFailure`), links the log and offers Set up local voice. A busy failure names the lock's holders from `/proc/locks` in its keyed line alone: `jarvis-setup: failed=setup=busy holder=<pid> program=<comm>`. `scripts/test-jarvis-setup.py` and `scripts/test-jarvis-setup-gate.js` pin it.
- Never read the core from the plugin snapshot; the daemon loads shared libraries from the VGS tree passed as argv. `scripts/smoke/rows/read-only-prefix.sh` pins it.
- Do add a wire type only in `JarvisProtocol.accept`, with both endpoint consumers; unknown types, extra fields and oversized lines fail. Never assign a daemon generation from the service. `scripts/test-jarvis-protocol.js` and `scripts/test-jarvis-daemon.js` pin both.
- Do exit 78 for a permanent configuration failure and never retry it; never let a successful hello replenish the restart allowance. `scripts/smoke/rows/jarvis.sh` pins both.
- Do publish every settings offer list through the plugin's `choices` status; a discovery failure never changes a configured provider or device. `scripts/smoke/rows/settings.sh` pins it.
- Never fall back to a default for a status shape the service does not produce, never infer readiness from an installer's exit status or a directory's presence, and never map a scratch or helper failure to exit 77. `scripts/test-jarvis-widget.js` and `scripts/test-jarvis-setup.py` pin them.
- Do use `shell/plugins/vgs.jarvis/backend/fleet-setup.js` as the shared installer and lock owner for startup mailbox migration and the Jarvis page action. After initial home layout, startup may install once for a home with only the previous reader. This migration is an exception to [commands-are-data.md § Consent](commands-are-data.md#consent). A ready home or a refused canonical entry starts no automatic install. Readiness probes never install.
- Do repair a Kendex-owned Home through interactive refresh targeted at that Home, under the fleet installer's lock and namespace lease. Keep terminal input and output connected. Installation Repair uses the host user and PID namespaces so elevation and restart can reach the installation. The same lease owner keeps the repair lock through child cleanup. It waits for privileged children the user cannot signal. A VGS-owned Home with an incomplete shipped render reports a damaged VGS install and uses `vgshell self repair`, never Kendex or a second package writer. The private Home repair record supplies a failure cause, never readiness. On terminal completion the service judges the currently selected Home again. `scripts/test-jarvis-home-repair.js` and the `jarvis-home-repair` smoke row pin these routes.
- Do consume the automatic attempt durably in the home before setup releases or writes package files. Failure and interruption keep the attempt consumed across daemon restarts. An unreadable or unsavable attempt record starts no automatic install. Keep explicit retry on the Jarvis page through the same installer. Bound the installer lifetime, end its descendants on cancellation, and recheck the selected home before publishing completion. Review holds these rules.
- Do keep a coding task the one child that outlives the daemon, reached only through records written by rename under one lock ([D072](../decisions/D072-coding-task-records-and-four-fact-state.md)); never put a goal or a path in TUI arguments. `scripts/test-jarvis-task-runner.js` pins it.
- Do copy shared product skills from `packaging/jarvis-home/skills/own/` through `Home.layout`'s existing file record, in VGS-owned and kendex-owned homes alike. Keep kendex's claimed paths and foreign files unchanged. Never add a second ownership record or follow a skill link. `scripts/test-jarvis-home.js` holds copying, discovery and interrupted-copy recovery.

### Setup, keys and the session

- Do open a setup window only from the user's choice on the Jarvis page, through the core's choice hook (`shell.status.handleChoice`). A settings change, a file edit, a reload or a migration opens none. A Voice provider choice opens at most one window, the one `SetupGate.providerWindow` names: Add a key for a cloud voice with none of its keys stored, else the local voice download for a voice that hears on this computer while no tier is ready. The step the window did not open stays the Voice step's action on Setup. A Local voice model choice opens its download (`LocalTier`). `scripts/test-jarvis-setup-gate.js`, `scripts/smoke/rows/jarvis-setup.sh` and `scripts/smoke/rows/jarvis-page.sh` pin it.
- Do store a voice key only through the add-key window, the Voice key field's Add a key. The window names the company of the Voice provider, opens only that company's key page and reads the key in a masked box. `keys.js add-check` refuses a full or unreadable key list before the box asks. `keys.js add-key` reads the key from the window's pipe, drops one trailing LF, writes it to `secret-tool store` on stdin and zeroes the buffer ([secrets.md](secrets.md)). Jarvis then selects the key the run added (`SetupGate.voiceAdded`). A provider change unsets a Voice key of another provider, and Local writes none (`SetupGate.voiceChoice`). `scripts/test-jarvis-secrets.js` pins the window and the store, `scripts/test-jarvis-accounts.js` the selection of the added key and the provider change, and `scripts/smoke/rows/jarvis-page.sh` that Add a key opens the window.
- Do rewrite a stored `voiceProvider: "auto"` in place on the service's first settings read, before anything reads the provider and without waiting for the account probe: Realtime while the Voice key setting names a key and Talk mode is not Always, else Local ([D107](../decisions/D107-format-change-ships-its-migration.md)). A key's id does not tell its provider, so a Gemini or ElevenLabs key named under Auto leaves Realtime asking for an OpenAI key; the daemon never sends a key to another provider. No other reader accepts `"auto"`. `scripts/test-jarvis-setup-gate.js` pins it.
- Do bind a microphone check's result to the source it heard. The daemon's snapshot carries `checkSource`, the source a capture hears (`Audio.device`: the Microphone setting, else the default source; the default always for dictation), and snapshots again when Audio reports a new one. A cloud voice keeps the result for the same source. A snapshot naming another source resets it to Check again with its reason. `scripts/test-jarvis-session.js` pins it.
- Do read the Jarvis session only through `backend/session-control.js`, whose answer is a contract state or a block. A run outside the contract reads `blocked unread` and writes one keyed stderr line, `jarvis: session-<verb>=timeout|exit=N|signal|spawn|unaccepted`. Each block names its own cause and a working action in `SetupGate.SESSION_BLOCKS`: Repair for `package`, Retry for `unread` and for `blocked trust-required` (with the package's own detail line), the Home folder link for `vgs-package`, `home-link`, `home-kind` and `home-unreadable`, and the field's link for `no-account`, `not-app` and `no-home`. The session is optional: no block makes Jarvis not ready. `scripts/test-jarvis-session-control.js`, `scripts/test-jarvis-setup-gate.js` and `scripts/smoke/rows/jarvis-session.sh` pin each.
- Never offer a session for a home VGS laid out, whose render ships no `jarvis-session`: its row reads Not offered in this home folder, and voice works without it.
- Do log a session block to fix or a failure as `jarvis-session: <verb>=blocked block=<b>|failed[ reason=<r>] cause=<first stderr line>`, and `jarvis: session-account=<reason>` when the account label cannot be read.
- Do name an account `<provider label>, <sign-in email or login>`, the provider alone while the email is unknown, and a stored key `<provider label>, <stored name>`; never a folder name or alias. The session row's `names.account` is that label, read when session-control answers: the vendor's status command within `COMMAND_MS`, and for Codex the account read within `EMAIL_MS`. `scripts/test-jarvis-accounts.js`, `scripts/test-jarvis-accounts-tui.js` and `scripts/test-jarvis-session-control.js` pin each.
- Do let a click on the Jarvis widget open the console, or resume while the Resume offer stands; mute only from the Mute key and the Jarvis menu's Mute microphone row. `scripts/qml-tests/tst_jarvis_widget.qml` and `scripts/smoke/rows/jarvis-widget.sh` pin it.
- Do draw the Jarvis menu from `WidgetView.menuEntries` alone: Mute microphone, Mute Jarvis's voice, Stop Jarvis and Key hints, each sending its key's intent or opening `page:vgs.jarvis/Settings/Keys`. The bar widget's right-click menu holds it, and so does the overlay's while the overlay is active; Stop cancels a held request as the Stop key does. `scripts/qml-tests/tst_jarvis_widget.qml`, `scripts/qml-tests/tst_jarvis_overlay.qml` and `scripts/smoke/rows/jarvis-bubble.sh` pin it.
- Do keep one actionable next step in a widget tooltip, with at most one link (`WidgetView.oneLink`). A home folder fault leads to its Setup row and the files to repair. An optional session's failure links its repair step without making Jarvis not ready (`SetupGate.sessionSummary`). `scripts/test-jarvis-widget.js` pins it. The widget's presentation and targets live in `WidgetView.js`; the [plugin help](../../shell/plugins/vgs.jarvis/README.md#setup) shows how to open the Console and change its keys.
- Never enable a console action that cannot work. Explain why an action is unavailable; Send takes its reason from `Session.sayRefusal`. Offer speech-only guidance instead of typed input under a duplex voice. `scripts/smoke/rows/jarvis-console.sh` pins it.

### Overlay motion

- Do move Jarvis's orb in every state, each at its own base rate with its own character, and let input add to that rate; only the rate changes from state to state, never still against moving (owner, overseer directive 1793742833). The base rates are `Appearance.js` `state` and the table below states them. The orb's clocks move while it shows in a shown window and `motion.scale` is above 0, in every state and at every level, and stop at motion scale 0. A state that can show all day, armed, idle, Muting and error, draws at most its look's `frameRate`, 30 frames a second, through a `Timer`; the others draw every frame the screen does through a `FrameAnimation`, which, while it runs, makes its window present every frame (`ParticleOrb.qml` states the Qt source). The clocks advance by the time that passed, so the frame rate never changes how fast the orb moves. Stopping is not paced: it shows only while Jarvis stops. Input is the capture level while listening and the playback level while speaking, through one curve, `(1 - e^(-k x)) / (1 - e^(-k))` with `k` = `orb.response`, 3: continuous and rising, 0 at 0 and 1 at 1, so quiet speech (level 0.1) moves the orb 27% of the way and a loud voice (0.5) 82%; `c` in the table is the curve's output. `scripts/qml-tests/tst_jarvis_orb.qml` pins the table and the curve, holds the clocks moving in every state and stopped at motion scale 0, and holds a paced state drawing at most its rate and an active one every frame; `scripts/smoke/rows/jarvis-bubble.sh` reads swapped frames on a real layer in four states, muting, speaking, armed and error, none over the fault at motion scale 0, and the armed orb swapping at most its look's rate over 2 s against speaking swapping more. Speaking at playback level 1, the `jarvis-orb` record in `scripts/shader/ceilings.json`, is the stress case with the largest drawn area, and the armed orb, the state that can show all day, is measured directly as the `jarvis-orb-armed` record. Neither record bounds another state's cost: the shader's exits depend on its noise, so a smaller look can run more of its bounded work, and armed's highest GPU p90 at scale 1, 0.0382 ms, is 6.4% above speaking's, 0.0359 ms (`scripts/measure-shader.sh` calibration runs 1793752087-2 and 1793678713-2 on cachy, the records' `calibration_runs`). The whole armed overlay costs more than its shader, since its full-screen layer draws and presents each frame the orb draws. Drawing every frame, on cachy (RTX 5090, Vulkan, the nested sandbox's 1920x1080 output at 60 Hz, 2026-11-03, VGS-2210 fix round 2 run 1793757281-2), `vgshell run` started the armed `Bubble.qml` alone in a full-screen layer as the shell, and each reading spans 600 s, at motion scale 1 against the same overlay at motion scale 0: 60 frames a second against none (the window's `frameSwapped`); 33.3 ms of the shell process's CPU time a second against 0.0 ms, and 27.5 ms of the nested Hyprland's against 0.5 ms (`/proc/<pid>/stat`, utime plus stime); a window GPU frame time of 0.040 ms p50 and 0.042 ms p90 over 2346 frames of a further 40 s pass (Qt's `QSG_RHI_PROFILE` render loop log); a resident size of 314 MiB at 610 s, 6.2 MiB above its 10 s reading, against a flat 241 MiB (`scripts/sample-shell-memory.sh`, 11 samples 60 s apart); at host CPU pressure (some) of 2.1% and 2.8%. No budget in [validation.md](validation.md) bounds a cost a second or a resident growth over a day: the smoke's 1,174,016 KiB resident ceiling bounds a whole shell at its first stop, and 600 s, the sampler's floor, cannot tell warm-up from steady growth. Paced at 30 frames a second, the same scene on the same machine and output read, over 600 s, 30.3 frames a second, 19.95 ms of the shell's CPU time a second against 33.3 ms, and 15.09 ms of the nested Hyprland's against 27.5 ms, at host CPU pressure 3.1% (VGS-2210 fix round 3 run 1793761130-2, 2026-11-03); in the same run the overlay thinking, an active look, swapped 60.0 frames a second at 26.65 ms and 20.66 ms over 60 s. No 144 Hz reading is stated: with the sink's frame clock at 144 Hz and the monitor rule `1920x1080@144`, the nested Hyprland reported its output at 60 Hz and the thinking overlay swapped 62.5 frames a second (run 1793761806-2).

### Capture and records

- Do let the console read tasks and audit failures only from the bounded lists the daemon publishes; only the audit owner reads its store.
- Do treat a missing shell or lock value as locked; neither `locked` nor `ready` health permits capture. Never grant capture from a component's existence; the presented observation travels on the child's ordered wire. `scripts/test-jarvis-daemon.js` and `scripts/smoke/rows/jarvis-bubble.sh` pin both.
- Never start playback before Audio acknowledges the recorder closed, never queue microphone data for replay, and never add an echo loader whose success cannot be verified. `scripts/test-jarvis-session.js` and `scripts/test-jarvis-audio.js` pin it.
- Do admit one synthesized start cue when the user opens a conversation and one stop cue when it closes normally, for every voice. Session gates both with Sounds feedback and admits the stop cue after capture and old playback acknowledge closure. The cue owns no conversation resources; provider reconnects and utterance capture opens play none. `scripts/test-jarvis-session.js` and `scripts/test-jarvis-engine.js` pin it.
- Do take the local voice's final words from the core's dictation recording, which the daemon requests through `dictation.start` only once Session admitted the capture; the sidecar owns the wake word, the captions, turn detection and synthesis, and its end marker says only whether its voice activity heard speech: it loads no final recognizer and runs no offline decode. Jarvis plays its conversation cues for this voice too. The core lends no per-recording sound control, so voxtype also plays its recording tones while its Voice setting enables them. `scripts/test-jarvis-engine.js`, `scripts/test-jarvis-local-speech.py` and `scripts/test-jarvis-session.js` pin each.
- Do arm a wake capture only in Always mode while the chained engine is otherwise idle, feed it only to the daemon-owned sidecar, and never collect, release or audit its audio; refuse Always mode with `speech=always-local-voice` for a voice that cannot spot the word locally. The ElevenLabs voice only speaks over the local row, which still spots the word, so Always mode keeps it. A follow-up capture is the same Session conversation after a spoken reply, with no second listener. `scripts/test-jarvis-session.js`, `scripts/test-jarvis-engine.js` and `scripts/test-jarvis-local-speech.js` pin each.
- Never judge the wake phrase from a transcript's first word; the wake model judges it. A recognizer can mishear a short first word at a sharp onset ([VGS-1251](https://linear.app/vanillagreen/issue/VGS-1251/jarvis-mishears-the-first-word-of-a-fed-voice)).
- Never let talk or stop clear mute, never copy mute into the mode setting, and register talk through the core hold-shortcut contract. `scripts/smoke/rows/jarvis-keys.sh` pins it.
- Do mute only Jarvis's spoken words, and only at Audio's paced write. While Session's `voiceMute` is on, that write sends the speaker silence of the words' length, for a chained and a duplex voice alike. The start, stop and working sounds and a voice preview stay audible: the engine hands each playback source with `spoken`, false for a conversation cue or a preview, and marks the working sound it pushes into a spoken source as a tone, which Audio plays while it silences every other packet of that source. The reply, its playback deadline, its acknowledgement and the playback level run as for a heard reply. Keep voice mute in its own record, `voice-mute.json`, beside `mute.json`, and never let talk or stop clear it. The overlay's voice button and the Voice mute key send the `voice-mute` intent, and the overlay shows Jarvis's words only while voice mute is on; it never shows the user's words, and a caption of the user's words clears Jarvis's. `scripts/smoke/rows/jarvis-bubble.sh` pins the button, the key and the words. `scripts/test-jarvis-session.js`, `scripts/test-jarvis-audio.js`, `scripts/test-jarvis-engine.js`, `scripts/test-jarvis-live.js`, `scripts/test-jarvis-session-runner.js` and `scripts/test-jarvis-daemon.js` pin each.
- Do read a Talk release in Talk mode `hold` within `Session.TAP_MS` (Hyprland's default repeat delay) as a tap. A tap keeps listening, input `tapped`, until the next press or `Session.TAP_SILENCE_MS` after the last words heard: a chained engine's partials, or a cloud voice's captions of the user. That silence is chosen, not measured, and the tapped input holds it for every engine. Before any words, the bound runs from the tap or from the microphone opening. A tap that ends before the microphone opens, while the start sound plays or the bubble maps, listens once it opens. On a cloud voice a tap is one request: the voice's end of speech, its delegation, ends the tap, and the microphone stays closed after the reply. A longer press ends at release, a release after the capture failed is no tap, and a capture that fails ends a tap. `scripts/test-jarvis-session.js` pins it, and `scripts/smoke/rows/jarvis-keys.sh` taps and holds the real Talk bind.
- Do call `Audit.before` after authorization and before an executor or transfer starts, never put a value, image, transcript or key in a record, and use `cleanup` for stop, mute and teardown so an unwritable store cannot block privacy teardown. `scripts/test-jarvis-audit.js` and `scripts/test-jarvis-redact.js` pin each.
- Never write a brain's text to disk, with one exception: under the test-run marker `VGS_TEST_RUN=1` and an explicit `VGS_JARVIS_TRACE` path, the engine writes each brain turn's raw text to that file, which the self-test's record includes. `scripts/test-jarvis-engine.js` pins the marker, the path and the file.
- Do end a held request's answer capture when the hold ends, by confirm, cancel or timeout. The one capture that outlives a hold is a duplex conversation's, when its voice replaces the request. `scripts/test-jarvis-session.js` pins it.

### Adapters

- Do add a provider as one row in `Providers.js`; a row for another driver refuses `brain=driver`. `scripts/test-jarvis-providers.js` pins it.
- Do send only through the shared owner; a driver adds no transport, timer, SDK or credential reader, and a speech adapter sends only through the `net` owner it is handed. `scripts/test-jarvis-brain-anthropic.js`, `scripts/test-jarvis-brain-openai.js` and `scripts/test-jarvis-elevenlabs.js` pin it.
- Do pass every history item through `Policy.release` on every request, look the key up through `Secrets.lookup` at first need and zero it on close, and call `net.assertKeyTarget` before any keyring lookup. `scripts/test-jarvis-brain-openai.js`, `scripts/test-jarvis-live.js` and `scripts/test-jarvis-elevenlabs.js` pin each.
- Never read a provider's error text; fail `brain=stream-error` with the body unread, and never yield a tool call before the stream completes. `scripts/test-jarvis-brain-anthropic.js` pins both; `scripts/test-jarvis-elevenlabs.js` pins the unread body for a speech row.
- Do keep a sent, cancelled turn in history unanswered, answer every call it left before the next turn, and refuse `brain=context-limit` at the history bound; never summarise or drop a turn. `scripts/test-jarvis-engine.js` pins each.
- Do create every per-conversation resource inside the engine and release all in `end()`; a changed brain, provider, account, policy or `cloudVision` setting ends the conversation, and a chained transcription partial never reaches the brain. `scripts/test-jarvis-engine.js` pins it.
- Do keep every harness program in its private working folder, with its vendor's own memory off at launch, and hand the home folder's knowledge to every brain only through `Guidance.compose` and the `help`, `memory.search` and `memory.read` tools; never start a brain's program in the home, and never give it the home as its working folder or in its environment. ## Revisit when

Quickshell provides a stronger child lease, capture moves to a process the shell cannot own, or an echo implementation can verify both module acquisition and routing before admitting simultaneous capture and playback. A provider speaks neither a compatible wire nor a harness program, VGS gains an npm route, a vendor permits a subscription outside its own program, or a speech provider reports played-frame timing. An executor cannot supply typed arguments or trusted target facts, kernel confinement cannot mediate an operation, or Hyprland exposes atomic target-bound input.
