# The Jarvis daemon, its brains and its actions

Read before touching the Jarvis service, its daemon, a child it starts, its wire, its records, the capture indicator, a brain or speech adapter, a provider row, the tool bridge, a tool executor, a Setup step, a voice key, the Jarvis session row, the bar widget or the console.

## The approach

`vgs.jarvis` is one service that owns one Node child whose lease is its closed stdin; every module reaches the shell only through that child's wire, and every process the daemon starts dies with it. One wire judge, `JarvisProtocol.accept`, owns every shape in both directions, and the daemon owns the generation identity the service carries back. `Session` is the sole admission judge: capture opens only after the shell has presented the indicator, and withdraws when it disappears. The indicator is the service-owned passive orb layer while shown, or the bar J and its listening badge on the focused output while the orb is hidden ([D125](../decisions/D125-hidden-orb-capture-indicator.md)). A component's existence, a status file or a pending request never grants capture. Private records hold names, never values. A failure is a keyed `jarvis: <area>=<cause>` with no provider text, and readiness comes only from its one judge. The choices are [D064](../decisions/D064-jarvis-child-lease.md), [D070](../decisions/D070-jarvis-action-policy.md) and [D072](../decisions/D072-coding-task-records-and-four-fact-state.md).

Every brain reaches the model and the tools by the same controlled route. A brain is a wire adapter, whose driver sends only through `WireBrain.js`, or a harness adapter, the vendor's unmodified program behind the tool bridge ([D079](../decisions/D079-brains-wire-and-harness-adapters.md)). One engine owns the exact brain history across ordinary Talk closes ([D121](../decisions/D121-conversation-transport-lifetimes.md)). Each live generation owns its capture, voice transport and release grants; all close with that generation. The speech owner may renew an expiring provider connection within that generation. A retained native child holds its own context while its tool bridge refuses calls. Resume waits for cancellation, rejudges retained history labels and binds tool access to the new generation. The heard-prefix account remains a separate labelled item ([D089](../decisions/D089-jarvis-chained-engine-and-heard-prefix.md)). The daemon owns the local speech sidecar across conversations. Every item leaves through release, then audit, then the one network door that [jarvis-outbound.md](jarvis-outbound.md) governs. An account's Verified comes only from one explicit inference request the user started, judged by the same release owner.

Every action, a brain's tool call and a harness program's own approval request alike, passes one policy gate and reports only what it read back. An executor registers only after its own readiness probe passes, and every call reaches it through one serial router, `shell/plugins/vgs.jarvis/backend/ToolRouter.js`, which owns the only confirmation identity ([D070](../decisions/D070-jarvis-action-policy.md)). A command that may already have acted reports `unknown`, never `failed`. A desktop change goes to the shell as a request, so `shell/Core/Dispatch.js` stays the one dispatch judge.

## Why

A pipe closes after a shell crash without QML teardown, where a parent-death signal alone misses a parent already dead. Linux clears the parent-death signal across fork and a process group misses a descendant that closed its pipes, so only the death of a namespace's init kills every descendant. The microphone owner must not outlive the indicator, so a sidecar is a leased child and never a service. An audit that stored a value would hold the secret it exists to keep out.

A harness tool left on would bypass the policy gate, and vendor terms allow a subscription only through the unmodified program. A provider error body can echo content or credentials, so it is cancelled unread. A chained brain has no server item to truncate, and bytes written overstate what was heard, so the heard prefix travels as a separate labelled item and history is never rewritten. A login-status or model-list reply proves an account exists, not that it answers, so only generated text verifies it.

A model can pick an action from untrusted file, page or screen content, so no executor may hold a second policy table or a confirm method; a serial hold removes Jarvis's own path to its own confirm key. A path judged by string can be swapped between the judgement and the open, so the executor rejudges at execution and walks held descriptors. A dispatcher answers `ok` without acting, and an application may keep its window open to ask about unsaved work, so only a read-back proves an effect. Registration proves nothing about confinement, so a shell tool is offered only after a real kernel probe answers.

## Rules

### Process and wire

- Do end the child by closing its stdin; never add a systemd unit or a detached keeper. `scripts/test-jarvis-daemon.js` and `scripts/smoke/rows/jarvis.sh` pin it.
- Do start every daemon child through `setpriv --pdeathsig KILL` with a parent check, run audio children inside a PID namespace that dies with the daemon, and give each child an explicit environment with no key and no `VGSHELL_RUNNER_PID`. `scripts/test-jarvis-audio-daemon.js`, `scripts/test-jarvis-audio.js` and `scripts/test-jarvis-desktop-tools.js` pin each.
- Never fall back to a host process, a unit or a privilege prompt when user namespaces are refused; report an audio fault. Gap: no test refuses user namespaces.
- Do pick the local tier in `setup-local` from the machine's NVIDIA GPU memory, RAM and CPU threads against each tier's measured need, with no hand step. The Jarvis page's Local voice choice overrides the pick. With no argument the setup window installs the tier the setting names. A failed run keeps the setting; a cancelled (exit 130) or finished run writes the ready tier back (`SetupGate.tierAfterRun`). `scripts/test-jarvis-setup.py`, `scripts/test-jarvis-setup-gate.js` and `scripts/smoke/rows/jarvis-setup.sh` pin each.
- Do let the daemon own the local speech sidecar across conversations and close it on daemon teardown and for a local voice setup run. The window's `setup-local release` asks the shell (`local-setup begin`), which takes the ask from the run's launch on, since the core's `shell.tui.state` reads a run live before any record of it is listed, and the shell sends `local-setup` `{running: true}`; a daemon still starting is told once it is ready. The daemon then ends a live local conversation or check with `speech=local-setting-up` and closes the sidecar. It answers `{}` only once the sidecar has exited and released its shared hold on `local-setup.lock`. It starts no sidecar until `{running: false}` or a daemon restart, then starts it on the new publication. Never write under the plugin directory from a child. `scripts/test-jarvis-engine.js`, `scripts/test-jarvis-protocol.js`, `scripts/test-jarvis-local-speech.js`, `scripts/smoke/rows/jarvis-setup.sh` and `scripts/smoke/rows/read-only-prefix.sh` pin each.
- Do record a failed local voice setup in `local-setup-failed.json` in the Jarvis state folder, `{cause, tier, log}`, where `log` is `setup-local.log`, which holds the window's keyed lines, the children's error lines and the probe's output. `setup-local` writes it on every failed install, words every failure in its own plain line, and the next successful install removes it. The Voice step words it only for the tier the setting wants while that tier is not ready (`SetupGate.localFailure`), links the log and offers Set up local voice. A busy failure names the lock's holders from `/proc/locks` in its keyed line alone: `jarvis-setup: failed=setup=busy holder=<pid> program=<comm>`. `scripts/test-jarvis-setup.py` and `scripts/test-jarvis-setup-gate.js` pin it.
- Never read the core from the plugin snapshot; the daemon loads shared libraries from the VGS tree passed as argv. `scripts/smoke/rows/read-only-prefix.sh` pins it.
- Do add a wire type only in `JarvisProtocol.accept`, with both endpoint consumers; unknown types, extra fields and oversized lines fail. Never assign a daemon generation from the service. `scripts/test-jarvis-protocol.js` and `scripts/test-jarvis-daemon.js` pin both.
- Do exit 78 for a permanent configuration failure and never retry it; never let a successful hello replenish the restart allowance. `scripts/smoke/rows/jarvis.sh` pins both.
- Do publish every settings offer list through the plugin's `choices` status; a discovery failure never changes a configured provider or device. `scripts/smoke/rows/settings.sh` pins it.
- Never fall back to a default for a status shape the service does not produce, never infer readiness from an installer's exit status or a directory's presence, and never map a scratch or helper failure to exit 77. `scripts/test-jarvis-widget.js` and `scripts/test-jarvis-setup.py` pin them.
- Do use `shell/plugins/vgs.jarvis/backend/fleet-setup.js` as the shared installer and lock owner for startup mailbox migration and the Jarvis page action. After initial home layout, startup may install once for a home with only the previous reader. This migration is an exception to [commands-are-data.md § Consent](commands-are-data.md#consent). A ready home or a refused canonical entry starts no automatic install. Readiness probes never install.
- Do repair a Kendex-owned Home through interactive refresh targeted at that Home, under the fleet installer's lock and namespace lease. Keep terminal input and output connected. Installation Repair uses the host user and PID namespaces so elevation and restart can reach the installation. The same lease owner keeps the repair lock through child cleanup. It waits for privileged children the user cannot signal. A VGS-owned Home with an incomplete shipped render reports a damaged VGS install and uses `vgshell self repair`, never Kendex or a second package writer. The private Home repair record supplies a failure cause, never readiness. On terminal completion the service judges the currently selected Home again. `scripts/test-jarvis-home-repair.js` and the `jarvis-home-repair` smoke row pin these routes.
- Do consume the automatic attempt durably in the home before setup releases or writes package files. Failure and interruption keep the attempt consumed across daemon restarts. An unreadable or unsavable attempt record starts no automatic install. Keep explicit retry on the Jarvis page through the same installer. Bound the installer lifetime, end its descendants on cancellation, and recheck the selected home before publishing completion. Review holds these rules.
- Do keep a coding task the one child that outlives the daemon, reached only through records written by rename under one lock ([D072](../decisions/D072-coding-task-records-and-four-fact-state.md)); never put a goal or a path in TUI arguments. `scripts/test-jarvis-task-runner.js` pins it.
- Do copy shared product skills from `packaging/jarvis-home/skills/own/` through `Home.layout`'s existing file record, in VGS-owned and kendex-owned homes alike. Keep kendex's claimed paths and foreign files unchanged. Never add a second ownership record or follow a skill link. `scripts/test-jarvis-home.js` holds copying, discovery and interrupted-copy recovery.

### Setup, keys and the session

- Do open a setup window only from the user's choice on the Jarvis page, through the core's choice hook (`shell.status.handleChoice`). A settings change, a file edit, a reload or a migration opens none. A Voice provider choice opens at most one window, the one `SetupGate.providerWindow` names: Add a key for a cloud voice with none of its keys stored, else the local voice download for a voice that hears on this computer while no tier is ready. The step the window did not open stays the Voice step's action on Setup. A Local voice model choice opens its download (`LocalTier`). `scripts/test-jarvis-setup-gate.js`, `scripts/smoke/rows/jarvis-setup.sh` and `scripts/smoke/rows/jarvis-page.sh` pin it.
- Do store a voice key only through the add-key window, the Voice key field's Add a key. The window names the company of the Voice provider, opens only that company's key page and reads the key in a masked box. `keys.js add-check` refuses a full or unreadable key list before the box asks. `keys.js add-key` reads the key from the window's pipe, drops one trailing LF, writes it to `secret-tool store` on stdin and zeroes the buffer ([secrets.md](secrets.md)). Jarvis then selects the key the run added (`SetupGate.voiceAdded`). A provider change unsets a Voice key of another provider, and Local writes none (`SetupGate.voiceChoice`). `scripts/test-jarvis-secrets.js` pins the window and the store, `scripts/test-jarvis-accounts.js` the selection of the added key and the provider change, and `scripts/smoke/rows/jarvis-page.sh` that Add a key opens the window.
- Do convert saved Talk settings in the configuration owner before runtime reads them ([D107](../decisions/D107-format-change-ships-its-migration.md)). `ConfigLogic.migrateConfig` preserves skipped-release `voiceProvider: "auto"` semantics before removing the former mode: a saved voice key outside former Always selects Realtime; otherwise Local. Preserve an existing valid held-microphone preference and remove the former mode and privacy-Mute binding. No service-side old-form reader remains. `scripts/test-plugin-logic.js` and `scripts/qml-tests/tst_config_writes.qml` pin it.
- Do bind a microphone check's result to the source it heard. The daemon's snapshot carries `checkSource`, the source `Audio.device` selects, including the judged echo-cancel source for native cloud voice and always the default for dictation. It snapshots again when Audio reports a new source. A cloud voice keeps the result for the same source. A snapshot naming another source invalidates that result; a voice that can check asks for another check. `scripts/test-jarvis-session.js` pins it.
- Do read the Jarvis session only through `backend/session-control.js`, whose answer is a contract state or a block. A run outside the contract reads `blocked unread` and writes one keyed stderr line, `jarvis: session-<verb>=timeout|exit=N|signal|spawn|unaccepted`. Each block names its own cause and a working action in `SetupGate.SESSION_BLOCKS`: Repair for `package`, Retry for `unread` and for `blocked trust-required` (with the package's own detail line), the Home folder link for `vgs-package`, `home-link`, `home-kind` and `home-unreadable`, and the field's link for `no-account`, `not-app` and `no-home`. No session block makes voice Jarvis not ready. While Start Jarvis at boot is off, an unmade choice stays optional; while it is on, a blocked boot build reads as a warning with its fix. `scripts/test-jarvis-session-control.js`, `scripts/test-jarvis-setup-gate.js` and `scripts/smoke/rows/jarvis-session.sh` pin each.
- Never offer a session for a home VGS laid out, whose render ships no `jarvis-session`. Voice works without it.
- Do log a session block to fix or a failure as `jarvis-session: <verb>=blocked block=<b>|failed[ reason=<r>] cause=<first stderr line>`, and `jarvis: session-account=<reason>` when the account label cannot be read. While Start Jarvis at boot is on, log every blocked build, including an unmade choice and the package's own block, in that same form.
- Do start a boot resume through the package's `start --harness H --account A --mode resume --origin boot`. An empty Account uses the record's harness and account; a set Account stays the selection, including a selection VGS cannot resolve, which stays blocked. The package alone judges resume or new. `scripts/test-jarvis-session-control.js` pins this route.
- Do name an account `<provider label>, <sign-in email or login>`, the provider alone while the email is unknown, and a stored key `<provider label>, <stored name>`; never a folder name or alias. The session row's `names.account` is that label, read when session-control answers: the vendor's status command within `COMMAND_MS`, and for Codex the account read within `EMAIL_MS`. `scripts/test-jarvis-accounts.js`, `scripts/test-jarvis-accounts-tui.js` and `scripts/test-jarvis-session-control.js` pin each.
- Do let a click on the Jarvis widget open the console. Its flyout shows status and a required recovery link; omit key, model and voice-provider details. The console keeps its own information. `scripts/qml-tests/tst_jarvis_widget.qml` and `scripts/smoke/rows/jarvis-widget.sh` pin it.
- Do show Jarvis's reply card under the J on the focused output while Jarvis Voice is muted or the orb is hidden: the newest answer of the current conversation cut at its first 4 lines, the words as Jarvis speaks them while the voice is on, or a fault in its plain words with its Settings link as its only action. A new answer replaces the card. It hides `replyCard.duration` after the answer settles, held while the pointer is on it. A click on an answer, or the Open Jarvis console shortcut while the card shows, opens the console at that answer and marks it. While the card shows a fault, the overlay's hidden-orb fault line steps aside, and a top notification stack stands below the card through the bar host's covers. The service owns the card (`WidgetView.replyCard`, the `replyCard` status) and the console reads the conversation it already holds (owner, VGS-2339). `scripts/test-jarvis-widget.js`, `scripts/qml-tests/tst_jarvis_reply_card.qml` and `scripts/smoke/rows/jarvis-reply.sh` pin it.
- Do draw the Jarvis menu from `WidgetView.menuEntries` alone. Put independent voice mute before system microphone mute; Stop interrupts current work while keeping the conversation. New conversation follows Stop and clears brain context while preserving whether the conversation is open. A missing or unbound default system source disables its action with a reason, never claims unmuted, and never blocks Talk or typing. Follow that source through one PipeWire tracker and publish its actual mute to the bar and orb. `scripts/qml-tests/tst_jarvis_widget.qml`, `scripts/qml-tests/tst_jarvis_overlay.qml` and `scripts/smoke/rows/jarvis-bubble.sh` pin it.
- Do keep one actionable recovery link in a problem or setup-needed widget tooltip (`WidgetView.view`). Derive it from the existing state reading, never a second classifier. `scripts/test-jarvis-widget.js` pins it. The widget's presentation and targets live in `WidgetView.js`; the [plugin help](../../shell/plugins/vgs.jarvis/README.md#setup) shows how to open the Console and change its keys.
- Never enable a console action that cannot work. Explain why an action is unavailable; Send takes its reason from `Session.sayRefusal`. Offer speech-only guidance instead of typed input under a duplex voice. `scripts/smoke/rows/jarvis-console.sh` pins it.

### Overlay motion

- Do move the orb in every visible state at the base rate its look defines. Input adds to that rate; silence does not stop it. `Appearance.js` owns the values. `ParticleOrb.qml` owns the clocks and the Qt constraints that keep an idle, system-muted or faulted orb paced. Motion scale zero stops every clock. `scripts/qml-tests/tst_jarvis_orb.qml` and `scripts/smoke/rows/jarvis-bubble.sh` hold motion and pacing.
- Do bind the open conversation's resting look to idle. Closing removes the orb; a held release keeps it visible. No wake-listening state remains.
- Do measure each shader workload under its own scene. Speaking at playback level one is the largest drawn orb, but its shader exits depend on its noise, so its ceiling bounds no other state. `scripts/shader/Scene.qml` declares measured scenes and `scripts/shader/ceilings.json` holds their provenance. The retired armed scene supplies no idle ceiling.

### Capture and records

- Do let the console read tasks and audit failures only from the bounded lists the daemon publishes; only the audit owner reads its store.
- Do treat a missing shell or lock value as locked; neither `locked` nor `ready` health permits capture. Never grant capture from a component's existence; the presented observation travels on the child's ordered wire. `scripts/test-jarvis-daemon.js` and `scripts/smoke/rows/jarvis-bubble.sh` pin both.
- Do let Session admit simultaneous capture and reply playback only for Realtime or Gemini when `EchoCancel.read` accepts the owned native configuration, `Audio.echoGraph` judges its connected physical route and `Audio.echoActive` excludes retiring physical audio children. Local and ElevenLabs, microphone checks and conversation tones wait for the recorder's close acknowledgment. Route loss revokes overlap without bypassing indicator, lock, generation or cleanup acknowledgments. Never queue microphone data for replay. `scripts/test-jarvis-session.js` and `scripts/test-jarvis-audio.js` hold these contracts.
- Do start echo-cancel setup only from its declared TUI action after the user confirms its physical targets and file. Preserve foreign files, write only the owned drop-in atomically, and load no module or restart an audio service. Judge installation separately from the connected active route; installer exit zero grants no overlap. Review holds setup consent and ownership; the Audio and setup fixtures hold file and graph refusal contracts.
- Do admit one synthesized start cue when the user opens a conversation and one stop cue when it closes normally, for every voice. Session gates both with Sounds feedback and admits the stop cue after capture and old playback acknowledge closure. The cue owns no conversation resources; provider reconnects and utterance capture opens play none. `scripts/test-jarvis-session.js` and `scripts/test-jarvis-engine.js` pin it.
- Do take the local voice's final words from the core's dictation recording, which the daemon requests through `dictation.start` only once Session admitted the capture; the sidecar owns captions, turn detection, explicit microphone checks and synthesis, and its end marker says only whether its voice activity heard speech: it loads no final recognizer and runs no offline decode. Jarvis plays its conversation cues for this voice too. The core lends no per-recording sound control, so voxtype also plays its recording tones while its Voice setting enables them. `scripts/test-jarvis-engine.js`, `scripts/test-jarvis-local-speech.py` and `scripts/test-jarvis-session.js` pin each.
- Do register Talk through the core hold-shortcut contract. Its unchecked setting opens a conversation until the next press; a checked setting admits capture only during the hold. A long release closes the microphone and keeps the conversation. A short empty tap closes normally, judged by an actual empty local result, no committed cloud input, or an explicit empty native transcript; missing captions prove nothing. `scripts/test-jarvis-session.js` and `scripts/smoke/rows/jarvis-keys.sh` pin it.
- Do mute only Jarvis's spoken words, and only at Audio's paced write. While Session's `voiceMute` is on, that write sends the speaker silence of the words' length, for a chained and a duplex voice alike. The start, stop and working sounds and a voice preview stay audible: the engine hands each playback source with `spoken`, false for a conversation cue or a preview, and marks the working sound it pushes into a spoken source as a tone, which Audio plays while it silences every other packet of that source. The reply, its playback deadline, its acknowledgement and the playback level run as for a heard reply. Keep voice mute in its own record, `voice-mute.json`, and never let Talk or Stop clear it. The overlay's voice button and the Voice mute key send the `voice-mute` intent, and the overlay shows Jarvis's words only while voice mute is on; it never shows the user's words, and a caption of the user's words clears Jarvis's. `scripts/smoke/rows/jarvis-bubble.sh` pins the button, the key and the words. `scripts/test-jarvis-session.js`, `scripts/test-jarvis-audio.js`, `scripts/test-jarvis-engine.js`, `scripts/test-jarvis-live.js`, `scripts/test-jarvis-session-runner.js` and `scripts/test-jarvis-daemon.js` pin each.
- Do let Session own the quiet-close deadline for every engine. Actual input or work refreshes it; snapshots and silence do not. Stop cancels the current reply, held request or cancellable tool without changing the conversation identity or playing an end cue. The open orb remains after a held release, and unchecked input resumes after reply or approval cleanup. `scripts/test-jarvis-session.js` pins it.
- Do call `Audit.before` after authorization and before an executor or transfer starts, never put a value, image, transcript or key in a record, and use `cleanup` for Stop and teardown so an unwritable store cannot block privacy teardown. `scripts/test-jarvis-audit.js` and `scripts/test-jarvis-redact.js` pin each.
- Never write a brain's text to disk, with one exception: under the test-run marker `VGS_TEST_RUN=1` and an explicit `VGS_JARVIS_TRACE` path, the engine writes each brain turn's raw text to that file, which the self-test's record includes. `scripts/test-jarvis-engine.js` pins the marker, the path and the file.
- Do close a held request's answer capture when confirm, deny or timeout ends the hold. The unchecked conversation resumes through the same capture admission gate, and checked input waits for its next hold. Deny addresses only the matching held request; it grants no authority to approve. `scripts/test-jarvis-session.js` pins it.

### Adapters

- Do add a provider as one row in `Providers.js`; a row for another driver refuses `brain=driver`. `scripts/test-jarvis-providers.js` pins it.
- Do send only through the shared owner; a driver adds no transport, timer, SDK or credential reader, and a speech adapter sends only through the `net` owner it is handed. `scripts/test-jarvis-brain-anthropic.js`, `scripts/test-jarvis-brain-openai.js` and `scripts/test-jarvis-elevenlabs.js` pin it.
- Do pass every history item through `Policy.release` on every request, look the key up through `Secrets.lookup` at first need and zero it on suspend and close, and call `net.assertKeyTarget` before any keyring lookup. `scripts/test-jarvis-brain-openai.js`, `scripts/test-jarvis-live.js` and `scripts/test-jarvis-elevenlabs.js` pin each.
- Never read a provider's error text; fail `brain=stream-error` with the body unread, and never yield a tool call before the stream completes. `scripts/test-jarvis-brain-anthropic.js` pins both; `scripts/test-jarvis-elevenlabs.js` pins the unread body for a speech row.
- Do keep a sent, cancelled turn in history unanswered and answer every call it left before the next turn. At the history bound, start fresh with an explanation and preserve the attempted next turn. An explicit New conversation clears the retained owner; shell or daemon restart retains none. Never summarise or reseed a retained brain as transcript text ([D121](../decisions/D121-conversation-transport-lifetimes.md)). `scripts/test-jarvis-engine.js` pins each.
- Do create each live resource inside the engine and release it on generation end. Retain only the suspended brain and its bounded context across ordinary close; changed brain, model, provider, account, home or policy settings clear it ([D121](../decisions/D121-conversation-transport-lifetimes.md)). Suspended bridges admit no tools, and pending results never cross a resume binding. A chained transcription partial never reaches the brain. `scripts/test-jarvis-engine.js` pins it.
- Do keep every harness program in its private working folder, with its vendor's own memory off at launch, and hand the home folder's knowledge to every brain only through `Guidance.compose` and the `help`, `memory.search` and `memory.read` tools; never start a brain's program in the home, and never give it the home as its working folder or in its environment. Read the base skill package from `.agents/skills/jarvis/` in every home, at the paths a kendex install writes; in a home whose kendex lock does not name the Jarvis skill, `Home.layout` copies the render VGS ships, never over a path kendex's lock names or a file it did not write, and replaces or removes only the files its record names ([D105](../decisions/D105-jarvis-home-folder.md)). `scripts/test-jarvis-claude.js`, `scripts/test-jarvis-codex.js`, `scripts/test-jarvis-copilot.js`, `scripts/test-jarvis-pi.js`, `scripts/test-jarvis-guidance.js` and `scripts/test-jarvis-home.js` pin each.
- Do load every home text whole whatever its size: the persona, `AGENTS.md`, the skill list, `memory/MEMORY.md` and the whole start text. Inform, never refuse: a text over its budget is a caution of the Home folder step that leaves Jarvis ready, and never holds the engine or fails a turn. Owner decision C, 2026-10-16 (Slack 1792195332): load, inform, never refuse for size. A start text larger than an AI model can take fails that turn alone, never the engine: the model or its app refuses the request, or a wire brain refuses a request over its 20 MiB bound before it sends (`brain=request-limit`). Never pass the start text in a program argument, which Linux bounds at 128 KiB (MAX_ARG_STRLEN): Claude Code and Pi read it from a 0600 file in their private folder, and Codex and Copilot over their stdin. A skill set over 256 entries still refuses, since that bound stops a runaway folder scan and is no size budget. `scripts/test-jarvis-guidance.js`, `scripts/test-jarvis-engine.js`, `scripts/test-jarvis-setup-gate.js` and `scripts/test-jarvis-claude.js` pin each.
- Do treat home text as `home` only while its writers are the user, VGS, and the Jarvis session acting on the owner's word as the owner's delegate, whose commits are the record; a writer outside that set reopens [D105](../decisions/D105-jarvis-home-folder.md).
- Do start a harness program with its tools off and the bridge as its only server; fail the turn when its init shows another tool or server, and end the conversation on any wire-order defect. `scripts/test-jarvis-claude.js` and `scripts/test-jarvis-codex.js` pin each.
- Do end a Pi conversation when any tool but the bridge's starts. Pi still starts the MCP servers the user configured, with its own environment, so never put the bridge's token in Pi's environment. `scripts/test-jarvis-pi.js` pins both.
- Do route a harness program's own approval request as `{kind: "approval"}` through the gate's `harness` executor, never offer harness rows to a brain, and refuse a program command outside the trusted profile. `scripts/test-jarvis-codex.js`, `scripts/test-jarvis-copilot.js` and `scripts/test-jarvis-policy.js` pin it.

- Do judge every Verify payload with `Accounts::released` and write `Audit.before` first; never let a login-status reply count as Verified, and never rebind a stored key to a selected target. `scripts/test-jarvis-account-verify.js` pins each.

## The canonical example

`shell/plugins/vgs.jarvis/backend/Audio.js` for a new child owner, `AnthropicMessages.js` for a wire driver, `ClaudeCode.js` for a harness adapter and `DesktopSession.js` for an executor. Copy them.

## Revisit when

Quickshell provides a stronger child lease, capture moves to a process the shell cannot own, or another speech recorder supports the judged echo-cancel route. A provider speaks neither a compatible wire nor a harness program, VGS gains an npm route, a vendor permits a subscription outside its own program, or a speech provider reports played-frame timing. An executor cannot supply typed arguments or trusted target facts, kernel confinement cannot mediate an operation, or Hyprland exposes atomic target-bound input.
