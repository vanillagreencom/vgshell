# Validation runner

Covers: scripts/validate, scripts/test-validate.sh, scripts/test-install-tree.sh, scripts/check-install-tree.sh, scripts/arch-packages.sh, scripts/main-run.sh

## Method

[D100](../decisions/D100-validation-selects-by-inputs.md) sets the testing method; it holds the reasons and the measurements.

- **Selection.** A change runs the rows its files reach. Each row declares its input globs, and a diff-scoped run selects a row when a changed path matches one of them. A row no changed file reaches does not run.
- **Declaration.** A row of `scripts/validate` declares its inputs in the fourth field of its line in the `rows=(` table. A nested smoke row declares its inputs in its own file, `scripts/smoke/rows/<row>.sh`, on one `# inputs: GLOB [GLOB...]` line in the file's leading comment block, the lines from its first that start with `#`. The globs are repository paths matched as the table's are, so `*` also crosses `/`, and the row's own file is always an input. A glob that is exactly another row's file, `scripts/smoke/rows/<other>.sh`, says this row reads that row's functions or the state it leaves, so a run that selects this row selects that one too, and the rows that one reads in turn. A wildcard over row files is a plain input and brings no row. A row file that no line of `scripts/smoke/rows.list` names, such as `jarvis-bubble.sh`, which `jarvis-keys.sh` runs, is not a row: `scripts/validate` reads no line from it, and the line of the row that runs it carries its inputs.
- **Smoke rows.** `scripts/smoke/rows.list` registers the rows: one row name a line, in run order, with the reasons for the order on comment lines that start with `#`; blank lines are skipped. `scripts/qml-smoke.sh` reads it and refuses a line that is no comment, blank or row name with `qml-smoke: refused: rows-list=malformed line=<n> path=<file>`. `scripts/qml-smoke.sh --list-rows` names the rows in that order; with `--rows` it names the rows that run would hold, starting nothing. When a diff-scoped run selects the nested smoke, `scripts/validate` reads each listed row's input line and passes the rows to run as `scripts/qml-smoke.sh --rows <row>,<row>...`, so `--list` prints them. The runner skips each row not named and keeps its harness steps between rows. It refuses a name it does not hold with `qml-smoke: refused: argument=--rows value=<name> reason=unknown-row`.
- **Core.** A run that selects the nested smoke runs the `bar`, `hyprland-consent`, `session`, `start-order` and `auth-sentinel` rows whatever the diff holds, and the rows their lines name in turn: `session.sh` and `start-order.sh` bring `capabilities` and `plugins`. The bar and the session are what the other rows build on; `hyprland-consent` answers the consent dialog the first shell raises, which no other row answers; `auth-sentinel` reads the authentication log last, so its reading covers every row the run held. `start-order` ends by starting the sandbox's own tree over the default set, so a row a run selects after it reads a live shell with its services built and not the last control's copy. A break that stops the shell starting fails these rows, so a product file the harness copies or edits needs no harness line to be caught.
- **A declaration that cannot select runs the row.** A row file with no input line, more than one, an empty one, an unreadable file, or a glob that matches no tracked file runs on every change that selects the smoke. This never fails or blocks the run.
- **Every smoke row.** `scripts/smoke/harness.sh` carries an input line of the same form, naming the harness's own machinery: the libraries it sources, the probe, the Wayland helpers it builds, and the fixture plugin and Jarvis world every run starts with. A product file the harness copies or edits, `bin/vgshell` among them, goes on the line of each row that runs one of its commands itself, edits it, stands in for it or reads its output, not on the harness line. The harness's own `vgshell run`, `pid` and `ipc call`, and the `hypr state` and `theme follow` every shell start runs, go on no row's line: the core rows make them on every run that selects the smoke. The harness also sets what rows read whichever rows the run holds: the monitor size, the bar's reserved height and screen, and the stand-in terminal, written before any row. A change to `scripts/qml-smoke.sh`, which holds the latency budgets and the commands the sandbox hides, to `harness.sh`, or to a file its input line names runs every row: the command carries no `--rows`. A harness line that is missing, repeated, empty or unreadable, a row list or a tracked-file list `scripts/validate` cannot read runs every row too, and a `validate: smoke-rows=all reason=<reason>` line on stderr names why. A run that selects some rows prints `validate: smoke-rows=some selected=<n> total=<m> skipped=<k>`.
- **Row list.** `scripts/smoke/rows.list` is no harness input. A change to it runs the rows its added lines name, read from `git diff -U0 <base> -- scripts/smoke/rows.list`, with the core rows and the rows they read: a new or moved row runs, and a comment runs nothing. A removed line whose row the list no longer holds, while its file stays, runs each listed row whose input line names that file, since that row reads state the unlisted row no longer leaves. A new row's own file is a changed path too, so its line selects it either way. A row list git does not track, one the diff cannot read, or an added line that names no listed row runs every row, with `reason=rows-list-untracked`, `rows-list-diff-unreadable` or `rows-list-unlisted-line`. A moved row can change the state a later row reads without declaring it; the full run catches that.
- **Lane bound.** `scripts/smoke/rows.secs` holds each measured row's median seconds, and `smoke_bound_secs` in `scripts/validate` the bound, 60. A selection of some rows leaves out a row over the bound unless it is a core row, its own file changed or a selected row reads it, and prints `validate: smoke-row skipped=over-bound row=<row> secs=<s> bound=<b>`. A row with no line runs; a seconds file that cannot be read or holds a line of another form prints `validate: smoke-secs=unreadable` or `smoke-secs=malformed` and leaves every row in. A lane runs a skipped row by naming it to `scripts/qml-smoke.sh --rows`; `--full`, and with it the batch run on main, runs it. The harness prints `qml-smoke: row-secs row=<row> secs=<s>` after each row, the reading the file is refreshed from.
- **Full run.** `scripts/validate --full`, an unreadable diff, an unknown input that selects the full area, a direct `scripts/qml-smoke.sh` run with no `--rows` and the release check, `scripts/validate all --full`, run every row.
- **Smoke input self-check.** Whenever `scripts/validate` reads the input lines, it prints one line on stderr for each row file or harness line that cannot select: `validate: smoke-input row=<row> missing`, or `harness=scripts/smoke/harness.sh` for the harness, then `lines=<n>`, `empty`, `unreadable` or `glob=<glob> matches-nothing`, followed by the line to add or fix; the `unreadable` form names the file's path instead. A harness glob that matches no tracked file is reported, and still runs every row when it matches a changed path, such as a new, uncommitted helper. It also prints `validate: smoke-input row=<row> function=<name>` or `variable=<name>`, then `from=` the row files that define it and the line to fix, for each function a row calls, or variable it reads, that neither the row nor the harness defines but another listed row does, when the row's line names none of those files: under `--rows` or a diff-scoped run, that row fails whenever the defining row is not selected. A call is a word where a command stands, or the command operand of a function whose body runs `"$@"` after one literal `shift N`, such as `expect LABEL WANT CMD...`; the harness is `scripts/qml-smoke.sh`, `harness.sh` and the libraries it sources. A file the scan cannot read to its end prints `validate: smoke-input unparsed path=<file>`, and `reads=unreadable` says the scan did not run. State a row leaves on disk, such as a directory it creates, is beyond the scan: its reader still names that row's file by hand. The scan reads no product path, so a row's product inputs are its author's to name. The self-check lines never change the exit status of the run that prints them. The `smoke rows name the rows they read` row of the `tools` area runs the same scan on a change under `scripts/smoke/` or to `scripts/qml-smoke.sh`: it fails on a `function=`, `variable=` or `unparsed` line, and exits 77 when the scan could not run.
- **Controls.** `scripts/test-validate.sh` holds one must-fail control for each of these rules, each a copy of `scripts/validate` with that rule removed that wants the exact plan the loss gives: a row with no line, a glob that matches nothing, a row with two lines, an empty line, a row file that cannot be read, a changed path, the core rows, the row-file closure (with a cycle case), a harness change, a change to a file the harness line names, a harness with no input line, a runner change, a runner that lists no core row, a runner that lists no row, an unknown input and `--full`, a row over the bound, a row at it, a core row, a row whose own file changed and a row a selected row reads, each over the bound, a malformed seconds file and `--full` with a row over the bound, and a fix round after a rebase and one whose base HEAD holds; three more want the plan of a committed row list change, read from the commit before it: a moved row runs alone, a comment runs no row, and an unlisted row runs the rows that read it. Its self-check cases read the `validate: smoke-input` lines on a listing run and on a real one, which passes, and nine more copies each drop one rule of the function and variable check and want its line gone, or for a rule that exempts a read, the exempted line named: a call where a command stands, a call through a runner's command operand, a variable read, a file the scan cannot read to its end, a row file run through `smoke_row`, a row's own definitions, the harness's, the libraries it sources, and a row file the line names. The cases of the `tools` row want exit 1 for a function a row calls from a file its line does not name and for a file the scan cannot read to its end, exit 0 with both fixed, and exit 77 for an empty row list; its control is a copy whose row no longer fails on the line it reads. A copy of `scripts/qml-smoke.sh` whose row predicate holds every row is the control of `--list-rows` with `--rows`, and a copy without the line refusal, which lists a malformed line as a row, is the control of the row list read; copies without the empty and the unreadable refusals are the controls of `rows-list=empty` and `rows-list=unreadable`. No fixture reaches an unreadable tracked-file list: `git ls-files` fails only where the diff read before it fails too, which selects the full area first.

## Rows

- `scripts/validate` owns the commands and their input globs. A run selects by the changes from its base, including staged, unstaged and untracked files, and prints `validate: base=<commit> source=<source>`. A base HEAD no longer holds, as after a rebase, keeps only the paths the branch changes against its branch point, before or now, and prints `validate: scope=rebased`: main's changes in between are the batch run's. The base is the first of these that holds: `--changed BASE` (`argument`); `DEV_VALIDATE_BASE`, the fix-round base Kendex supplies; `VGS_VALIDATE_BASE`; the newest commit since the merge base that holds the tree the same area's last passing run in this worktree read (`last-pass`); and the default branch's merge base (`merge-base`). When no commit holds that tree, as after a rebase or on another branch, the merge base serves, and the run prints `validate: last-pass=ignored reason=no-commit-holds-tree tree=<tree>`. `--changed BASE` also sets the whitespace range; `--full` explicitly selects the whole area. Shared dependencies select every listed consumer; unknown source inputs or a failed diff select the full area. Documentation changes and agent-harness changes, under `.claude/`, `.codex/`, `.pi/`, `.github/`, `.bot-instructions/`, Kendex's own files and `.agents/` but the vgs-plugin skill, run repository checks without the product smoke. A selector change runs its own control rather than every product suite. Each executed row prints `validate: secs=<seconds> exit=<status> row=<label>`, and the final selected line carries total seconds. `scripts/test-validate.sh` checks selection and plants a forbidden import that escapes when its dependency edge is removed.
- On a readable diff-scoped run, `scripts/validate` exports `VGS_VALIDATE_CHANGED` as the NUL-delimited changed-path file it built for selection. A row may read that file to narrow its own work. The variable is unset on `--full`, an unreadable diff and an unknown input that selects the full area.
- The `runner CLI controls`, `requirement report controls` and `outdated controls` rows select bundled plugins by `shell/plugins/*/manifest.json`. Those suites run `bin/vgshell`, which reads bundled plugins through `bin/vgshell-scan`: manifest text, the manifest content hash and requirement probes. The `bundled manifests` row still selects on `shell/plugins/*`, so a scan failure on a plugin file still fails.
- The `user command text controls` row selects only the control script, bundled plugin manifests, `shell/Core/PluginLogic.js`, `shell/Core/PackageManagers.js`, `bin/*`, `config/requirements.json`, `scripts/qml_source.py` and `bin/lib/qml-library.js`. Its real-tree pass and coverage floor repeat the `user command text` row, which keeps `shell/*`.
- The nested smoke and nix flake rows do not select on root `LICENSE` or `README.md`. The smoke harness and the installer copy those files as opaque bytes. The install tree controls row keeps both and checks their installed presence.
- The repo rows always run. `whitespace_check` catches defects against the selected base. `rows_cover_tests` stops a test file with no validation row. `runtime_reads_no_scripts` keeps the installed runtime independent of `scripts/`. `runtime_writes_no_monitor_rule` refuses an `hl.monitor` call under `bin/`, `shell/` or `config/` ([hyprland-monitors.md](hyprland-monitors.md#invariants)). `private_keys_check` blocks private-key armor in the tree. `md_refs_check` protects links, heading routes, decision references and source citations across files the diff did not touch.
- The install tree check is selected when a shipped runtime file, root README, licence, installer or manifest changes. `scripts/test-install-tree.sh` installs with `DESTDIR` and `PREFIX` and runs `scripts/check-install-tree.sh`; what it proves and its controls are in [distribution.md § Install tree](distribution.md#install-tree). A new shipped file without a manifest update fails with the command to regenerate the manifest. A manifest change also selects `scripts/check-packaging.js`, its controls and `scripts/test-publish-aur.sh`, because the recipe check refuses a manifest without the first-install text.
- The nix flake check is selected when the flake, its lock, `config/requirements.json`, the installer, the manifest or a shipped file changes. Its area is `nix`, which `offline` leaves out, while the default `all` area selects it. It needs podman or docker and a route to `cache.nixos.org`, and exits 77 without either: [distribution-nix.md](distribution-nix.md).
- The Fedora checks are selected when a file under `packaging/fedora/`, `.copr/Makefile`, `VERSION`, `bin/vgshell`, the core requirements or a plugin manifest changes; a Fedora recipe change starts no nested smoke. `scripts/fedora-container.sh`, the Fedora install test, needs podman and the network and runs by hand before publication: [distribution-fedora.md](distribution-fedora.md).
- The README install section check's controls, whose first row runs the check on a scratch copy of the working tree's files the check reads, and the runner's host-side controls are `cli` rows. They select on `README.md`, `VERSION`, `bin/vgshell`, `bin/vgshell-scan`, `bin/lib/post-install.txt`, `install.sh`, `docs/architecture/runtime.md`, a recipe under `packaging/arch/` and a plugin under `shell/plugins/`. `scripts/readme-install.sh` needs podman and the network and runs by hand before a release. What the section must say and what each script holds it to: [install-guide.md](install-guide.md).
- **Last pass.** A run of an area that exits 0, never 1 or 77, records the tree it read in `<git-dir>/vgs-validated-<area>`, the worktree's own git directory, and prints `validate: last-pass=recorded area=<area> tree=<tree>`. The tree holds every tracked and untracked file git does not ignore, as the worktree holds it, committed or not, built in a scratch index; a clean worktree gives HEAD's tree. A run validated before its commit is therefore found once the commit holds the same files. A pass proves only the rows its own `scripts/validate` table selected, so when that commit's `scripts/validate` differs from the worktree's, the run prints `validate: last-pass=ignored reason=selector-changed` and the merge base serves: a table that now maps a path the branch changed before the pass reads the whole branch again. It records only when its base proves the whole branch, the merge base, an earlier pass or `--full`, and only when it reads the same tree at its start, before the diff that selects its rows, and at its end. Otherwise it prints `validate: last-pass=unrecorded reason=<reason>`: `named-base`, `content-changed`, `tree-unreadable`, `git-dir-unresolved` or `write-failed`. A run that records nothing keeps its exit status, since the merge base selects more, never less. `scripts/test-validate.sh` holds a control for each rule: a harness round validated before its commit leaves a fix round that runs only the fix's rows, another area reads no pass of the first, content that changes during the run records nothing, a rebase falls back to the merge base, a selector change after the pass reads the whole branch, each named base outranks the last pass, `--changed` outranks `DEV_VALIDATE_BASE`, and `--changed`, `DEV_VALIDATE_BASE`, a failing run and a run that exits 77 each record nothing.
- Validation is explicit, not a commit, push or merge gate. No branch rule exists, and no workflow runs on a push or a pull request; the one workflow is the nightly run of `main` ([validation.md § Nightly run](validation.md#nightly-run)). Run the affected checks once before delivery, and reuse the result while those inputs are unchanged. A fix round compares against the last validated commit, the last pass by default; submitting the same content does not start another full battery. After a restack, a fix round's `--changed` base is the rebased SHA of the last validated commit from the `rebase-map:` lines `worktree push` prints, or the default branch point when no commit maps, never the pre-rebase SHA, whose diff also lists every file the default branch changed since.
- The document byte ceiling row, `doc_limits_check`, reports a document over its ceiling before the change lands, since VGS runs no commit gate. It runs the doc-limits checker, which judges sizes alone and reads no base. A change fails when it puts `AGENTS.md`, a nested `AGENTS.md` or a `SKILL.md` over its ceiling; any other document over its ceiling prints a warning and passes: [policy](../../.agents/skills/doc-limits/references/policy.md). Its area is `tools`, and a Markdown file, a file under `docs/` or the checker's configuration selects it; a repo row would run on every change. It measures the tree the change will commit: a scratch copy of the index into which every Markdown and docs HTML file is added as the worktree holds it, untracked ones included. The real index is not written. A missing checker and a failed scratch index exit 77; a checker that cannot judge fails. `scripts/test-validate.sh` holds its controls.
- The markdown reference row, `md_refs_check`, runs the commit-guards md-refs checker `--all`, so a dead link, section route, decision reference or `<path>.md § Heading` citation in a source comment fails before the change lands. Any tracked file can carry a citation or be the target of one, so it is a repo row and runs on every change. It reads the same kind of scratch index as the ceiling row, built from every file the worktree holds. `COMMIT_GUARDS_MD_REFS_SOURCE_PATHS` in `kendex.settings.toml` adds the extensionless scripts to the checker's source extensions. A missing checker or a failed scratch index exits 77; a checker configuration error fails. `scripts/test-validate.sh` holds its controls.
- The private-key row, `private_keys_check`, refuses a PEM private-key armor line anywhere along a line in the tree. The tree is every tracked and untracked file that git does not ignore, as it is on disk. The row does not read the index or the commits in history; GitHub secret scanning covers pushed history. It covers every key type, such as RSA, EC and OPENSSH, and the PGP private key block; certificates and public keys pass. A refusal prints the path, the line number and the armor line only, never the key body. It is a repo row and runs on every change. It has no exemption list: a test that needs a key makes it at run time. The HTTPS redirect row of `scripts/test-theme-download.js` makes its own key and certificate with openssl, and the suite exits 77 without openssl. A file the check cannot read fails the row. `scripts/test-validate.sh` holds its controls.
- `scripts/landing-times.py` reads GitHub repository activity through `gh api` and reports branch landings from newest to oldest. It reports total minutes from open to land, wait minutes from ready to land, and medians for all landings, push landings, pull-request landings and wait time. It exits 77 when `gh` is missing, the activity feed cannot be read, a landing cannot be measured or fewer landings than requested exist. `scripts/test-landing-times.py` supplies its controls through a stand-in `gh`.
- `scripts/main-run.sh` runs whole areas on a detached worktree of main: the batch and nightly runs of [D100](../decisions/D100-validation-selects-by-inputs.md). Its header holds its result file and exit codes. `scripts/test-main-run.sh` runs it against a stand-in `scripts/validate` and holds its controls.
- `scripts/test-session-lock.sh` runs the real session-lock owner through that unit entry point. Its disposable copies remove requested-state observation, secure-state observation, provider freezing and lock preservation on holder unload. The nested session row reads the fixture's delivered capability and reactive state beside the lock holder: [capabilities.md](capabilities.md).
- `scripts/arch-packages.sh` builds and installs both Arch recipes in a rootless podman container, the area `package`. It needs podman and the Arch mirrors; a missing podman or a failed image pull, container start, system update or dependency download exits 77. `offline` leaves it out; the default `all` area selects it when a recipe under `packaging/arch/`, the installer, the post-install text `bin/lib/post-install.txt`, the browser theme writer `bin/vgshell-browser-policy`, the chromium target `themes/targets/chromium/*` or the release tarball builder changes. A recipe change does not start the nested smoke. [distribution-arch.md](distribution-arch.md) states what the build asserts.
