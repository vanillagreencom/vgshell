# One token table and one component library draw every surface

Read before touching tokens, the theme judge, `Theme`, `qs.Ui`, a plugin-owned look, pointer or keyboard input, focus, Settings fields or user-facing text.

## The approach

Every view meets the polish of Vercel's web app or a standard modern consumer app (owner, 2026-10-06). Values come from `shell/Commons/Tokens.js`; the pure `ThemeLogic.js` judge resolves them and `Theme` publishes frozen groups ([D015](../decisions/D015-tokens-are-a-judged-table.md)). Appearance values resolve once over the theme ([D104](../decisions/D104-appearance-values-over-the-theme.md)).

Screens compose `qs.Ui`. Controls extend QtQuick Templates ([D017](../decisions/D017-templates-and-path-icons.md)); overlays use anchored Quickshell popups ([D018](../decisions/D018-overlays-are-quickshell-popups.md)). Shared components own input, focus and spacing. A plugin-owned appearance table has only the inputs [D023](../decisions/D023-plugin-owned-appearance.md) permits. A look governs only the files that bind it, so one surface of a plugin can own its look while the plugin's other surfaces follow the theme ([D119](../decisions/D119-plugin-look-binds-per-surface.md)). Settings pages come from manifest schema ([D032](../decisions/D032-settings-plugin-and-manifest-settings-convention.md)).

## Why

A private control or literal drawing value creates a second style system that themes and shared accessibility fixes cannot reach. One owner per input behavior gives pointer, keyboard and touchpad users consistent access. Shared layout keeps text and controls aligned as content, fonts and scale change.

## Rules

### Tokens

- Read every drawing value from `Theme`. Publish each table group through a read-only Theme property. `scripts/check-design-tokens.py` checks literals, unknown paths and unpublished groups.
- Keep the table and judge free of imports, Qt objects and I/O. `scripts/test-theme-logic.js` runs them under Node.
- Keep the shipped layout scale on its grid and row heights independent of control size. `scripts/test-theme-logic.js` owns grid exceptions. Give a component-specific text style its own role instead of changing a shared role.
- Keep shipped and catalog themes above `ThemeLogic.readabilityShortfalls`' floors. `scripts/check-theme-contrast.js` checks them. Screensaver canvas stays fixed opaque black; its inks and both gradient phases use the judged screensaver tokens.
- Judge drawn hints at native size against their actual fill, not token contrast alone. Sample repeated straight-stroke interiors at the same positions before and after; use median RGB, excluding edges and isolated extremes. Measure stem width by summed coverage. Sample a peak-column center only when the stem spans at least two pixels or both neighbors have less than half coverage. Repeat text under its displayed disabled reason is exempt while that reason covers it. `scripts/test-theme-logic.js` checks rendering margins; screenshot review holds drawn readability and sampling.
- Identify a labelled button through readable label text. Its resting transparent fill and border need not meet the boundary floor. Keep modal fill and border readable above the dimmed page; on wallpaper where no border can hold, the fill carries the layer. `ThemeLogic.readabilityShortfalls` judges modal tokens.
- Use underlines and distinct indicator thicknesses for hover and selection over wallpaper when a colour change cannot distinguish them. Put failure and status text on the solid `carousel.failurePlate` with its danger mark. `scripts/test-theme-logic.js` checks the derived inks.
- Place leading icons through `Label.topForLeadingIcon`, never fixed offsets. Use the mixed-case x-height center, capitals center for capitals and figures, and the helper's ink-to-baseline reading for a single mixed-case link. Empty or wrapped links keep the general rule; underlines move no icon. Center two-line icons on the block and longer or variable-detail icons on the first line. `scripts/qml-tests/tst_label.qml` checks placement.
- Treat notification media as card media, centered on the card at one icon size. Automation notices alone may use an avatar with a smaller outcome badge. `scripts/qml-tests/tst_notification_media.qml` checks the exception.
- Give rest, hover, pressed, focus, disabled and checked distinct token states. Draw no hover or press on an item whose click changes nothing. Bar items and icon buttons have no hover fill. Keep visible press and keyboard focus. Review holds composition; `scripts/qml-tests/tst_button.qml` checks shared controls.
- Never replace `IconButton.background` or give an icon toggle a fill or border. Its glyph carries hover, press, checked and status tones. A filled variant keeps its rest fill; text toggles keep checked fills. `scripts/check-design-tokens.py` checks shared IconButton backgrounds; review holds private icon toggles. A surface that owns its look passes the glyph's rest, active and on colours and its ring colour through `restColor`, `activeColor`, `onColor` and `ringColor`; each defaults to the shared token. `scripts/qml-tests/tst_button.qml` checks those inputs.

### Appearance values

- Resolve user Appearance values only through `ThemeLogic.withAppearance`; unset values remain the theme's. Apply `APPEARANCE_RATIOS` only to user-set bases. `scripts/test-theme-logic.js` checks resolution.
- Use `radius.glass` for a zero-radius popup, menu, dialog or OSD only while glass is on. Preserve a positive theme or user radius and leave attached panels' `surface.radius` alone.
- Apply interface fonts only to sans and caps families. Monospace remains independent and terminal font belongs to theme targets. Accept no colour Appearance value ([D025](../decisions/D025-no-theme-override-layer.md)).
- Draw Hyprland-mapped values through `ValueSourceRow` ([D057](../decisions/D057-one-row-for-hyprland-mapped-values.md)). `scripts/qml-tests/tst_valuesourcerow.qml` checks the control.

### Appearance

- Load a plugin-owned look only from its declared appearance file. Bind once through `Theme.appearance`, use `look` paths and draw nothing on a null look. `PluginLogic.validateManifest` and `scripts/check-design-tokens.py` judge declarations and paths.
- Bind a look per surface. Only the files that bind `Theme.appearance` or read a `look` path their owner passes draw with the look; the plugin's other files read `Theme` and follow the theme, as Jarvis's console and bar widget do beside its overlay ([D119](../decisions/D119-plugin-look-binds-per-surface.md)). `scripts/test-check-design-tokens.py` checks both directions.
- Read no other Theme member in a file that draws with a look. Keep text above the shell's smallest text-role floor, excluding the hint-only key-name role, the owner-requested calendar weekday role and the owner-requested path chip role. `scripts/check-design-tokens.py` checks both boundaries.
- Keep launcher detail at least 4.5:1 against its fill and 1.25:1 apart from its resting title as drawn. The appearance table and `scripts/test-theme-logic.js` hold these contrast requirements.
- Use shadows only to lift light ink from dark glass, keyed to the ink once. Draw none for dark ink on light cards. `scripts/test-notifications-logic.js` checks notification shadows.
- Pass the look's own values to composed controls. The shared system key hint is the exception. GlassSurface takes the look's fill, rounding and elevation, but draws the standard surface while glass is off. Review holds supplied values.
- Draw a look's own button through `Button` with the look's values, never a private control: height, side padding, corner, rest, hover and pressed fills, border, label inks, ring and `shimmer`. The shimmer sweeps the label while the pointer rests on it, stops without another frame when the pointer leaves and stays still at motion scale zero. Its `shadow` draws the look's text shadow under the label and the shimmer. `scripts/qml-tests/tst_button.qml` checks the inputs and the shimmer; `scripts/qml-tests/tst_jarvis_prompt.qml` checks Jarvis's approval answers.
- Draw each line of a look's text over the look's text shadow, when the look sets one, through the line's own layer and `TextShadow`, so a still line redraws no blur. The look owns the shadow and the inks. `scripts/qml-tests/tst_textshadow.qml` checks the shadow and its stillness; `scripts/qml-tests/tst_jarvis_prompt.qml` and `tst_jarvis_words.qml` check Jarvis's lines, answers and inks.
- Draw Jarvis's overlay over its look's one fading `field`, dark with light ink in dark mode and white with dark ink in light mode. The orb's round particle centre has no flat filled disc. The orb and halo, the icon row while it shows and each content column's box share the field. Keep every line at 4.5:1 against its composed field and place content where the field reaches 60% of its box's peak. The look owns the values; `scripts/qml-tests/tst_jarvis_field.qml` checks placement, and rendered UI review judges the inks.

### Components

- Compose shared controls instead of private equivalents. Keep input width bounds in shared components and form rows, never in a page or plugin. Keep controls at the value column's start edge. Review holds composition.
- Use `TextField`'s `search` variant only for standalone search. Place it at the top of its content box, spanning the available width, with transparent fill and only a `border.thin` bottom rule. Its `textField.searchPadding` aligns the icon to the Plugins page's content edge; the shared icon gap, field height and container insets hold the remaining spacing. Keep form and password fields on the default filled, fully outlined variant. Theme and Wallpaper browsers keep fieldless typing-to-filter. Review holds placement; `scripts/qml-tests/tst_textfield.qml` checks the variant.
- Use `MessageRow` for conversations and asks, `ResultsFilter` for result filtering beside search, and `Badge`'s unread variant for unread counts. Keep accessible names complete. Their component files own geometry and interaction.
- Draw backgrounds through `Surface` or `GlassSurface` with the surface's standard token group. `glass-bypass` in `scripts/check-design-tokens.py` checks this boundary.
- Show widget counts only through `BarItem.count`; a second measured reading uses `detail`. No widget draws its own count (owner, Slack 1793643412.880369). Show a held state through `leadingIconName`, or an item's own icon when it stands alone, and name it in the label. Never use a badge for held state (Jarvis note 1793716109). `scripts/qml-tests/tst_baritem.qml` checks both forms.
- Show a live state, such as listening, working or a problem, through `BarItem.stateDot` in a `Theme.color` role, distinct from `count`; name the state in the label and tooltip too. A held state keeps its leading or standalone icon. `scripts/qml-tests/tst_baritem.qml` checks the dot and its place beside a count.
- Draw hints through `KeyHints`, without a private backing or shadow. Keep the shared theme hint on plugin-owned looks too, the narrow D023 exception. Inherit ground from the nearest ancestor through `HintGround.js`; never inspect siblings or their geometry. Supply `backgroundContext` only for a plate, private fill or outside surface the ancestor cannot publish. `scripts/qml-tests/tst_hintground.qml` checks inheritance.
- Keep bound field keys distinct from hints through `ShortcutField`'s value caps. Let `ThemeLogic` solve hint ink against its ground; preserve the readable floor when a preferred margin is unreachable. Use the shared row's action gap. Tokens and `scripts/test-theme-logic.js` own roles, margins and contrast.
- Add every new component to the Gallery in all variants and states, with a focus example when focusable. `scripts/smoke/rows/gallery.sh` checks coverage.
- Wrap values and menu choices instead of eliding them. Break at spaces through `LineBreak.atSpaces`, except an overwide word; keep accessible text unchanged. Preserve first-line alignment, surrounding gaps and popup placement across scale and hinting. `scripts/qml-tests/tst_settingfield.qml` and `tst_overlays.qml` check geometry. The authority is Jarvis decision 1792672338-3717266-30335.
- Disable through `disabledReason`, not `enabled: false` alone. Keep the control focusable, inert and faded, with a plain cause and next step on hover and focus. Offer `unlock` only for a single action that removes the condition. `scripts/check-disabled-reasons.py` reports missing reasons; `scripts/qml-tests/tst_disabledreason.qml` checks controls.
- Keep decorative components free of pointer handlers, processes, files, caches and secret stores ([D026](../decisions/D026-passive-layers-are-a-capability.md)). Review holds this boundary.
- Draw a fading field behind a passive layer's decoration through `RadialBackdrop`. Pass every input from the look; the component has no `Theme` default. It starts no frame of its own and draws on each frame its window draws. `scripts/qml-tests/tst_radialbackdrop.qml` checks the drawn field; `scripts/check-voiceorb-shader.py` checks its shader source and pack.

### Pointer

- Put `PointerCursor` on click targets and write no literal pointing-hand cursor. Exempt only click-away areas and scroll bars with a reason. Set views' `acceptedButtons` to `Qt.NoButton` and give each a `TouchpadScroll` bound to that view. `scripts/check-pointer-cursor.py` checks these boundaries.
- Scroll only for keyboard navigation, focus change, opening or explicit jump. Hover may change the plate and pick-list highlight, never keyboard focus or scroll position. `ScrollArea.qml` owns scroll inputs; `scripts/qml-tests/tst_overlays.qml` checks hover behavior.
- Give a passive layer's decoration pointer input only while it offers an action, and only on the part that offers it ([D026](../decisions/D026-passive-layers-are-a-capability.md)). Jarvis's overlay takes the pointer only in an active state, over the orb and each line and answer while it shows, and in a fault on the action's link alone; a right click opens the Jarvis menu. `scripts/qml-tests/tst_jarvis_overlay.qml` checks the region and the menu; `scripts/smoke/rows/jarvis-bubble.sh` checks the region on a real layer.

### Keyboard

- Give every click a keyboard path and every focusable item a focus indicator. `scripts/check-keyboard.py` checks them. Use a keyboard-path or focus-indicator marker only for an existing mechanism; review holds the marker's truth.
- Make a composite one Tab stop and move within it through `KeyNav`. Arrows never run actions. Hosts own Escape and initial focus: primary input, else list, else body, never an installing, removing or system-changing action. Show the focus ring only after navigation. Review holds these choices.
- Keep the bar unfocused except the widget-drag grab and its remove question. Give widget actions global shortcuts or launcher paths. Passive layers take no keyboard; the inbox supplies a toast's keyboard path. `scripts/smoke/rows/layers.sh` checks passive hosting; bar focus remains review-held.
- Keep a passive layer mapped with hidden content and empty mask while a popup holds a keyboard grab. Unmap after the last grab. `LayerHost.qml` owns this workaround and its upstream reason; remove it only when the required Hyprland release fixes focus return on layer unmap. `scripts/smoke/rows/layers.sh` checks it.

### Motion

- Read animation durations from motion tokens and stop untimed clocks when motion scale is zero. `scripts/check-design-tokens.py` checks literal durations; review holds untimed animation, and `scripts/qml-tests/tst_jarvis_orb.qml` checks Jarvis's orb.
- Run a shader clock only while its surface shows and motion scale is above zero, at the rate its look sets for the state it draws. A state that can stay up all day moves at a slow rate: Jarvis's orb moves in every state, an idle open conversation and a fault included, and only its rate changes (owner, overseer directive 1793742833; [jarvis.md § Overlay motion](jarvis.md#overlay-motion)). A paced state draws at most its look's frame rate and advances its clocks by the time that passed, so its motion keeps its speed. A running FrameAnimation makes its window present every frame, so a paced look runs none. `scripts/qml-tests/tst_jarvis_orb.qml` checks the clocks and the pacing; `scripts/smoke/rows/jarvis-bubble.sh` reads swapped frames on a real layer, and none at motion scale zero.
- Open and close bar flyouts with the shared fade and short anchor-edge slide. `scripts/smoke/rows/surfaces.sh` checks motion-scale stillness.
- Give each clickable list one `ListCursor` for hover and press. Rows use `lit` for selected ink and draw no hover fill of their own. Only Menu and Select change selection on hover. Pass plugin-owned timing and plate values into shared motion. `scripts/check-pointer-cursor.py` checks row hover.
- Call `rebuilt()` on row changes and `disarm()` for key steps or opening. Preserve pointed-row identity across rebuilds; a stationary pointer takes no new row. Key models that would recreate every row. `scripts/qml-tests/tst_listcursor.qml` checks ownership.
- Draw one hover plate per panel. A nested hover releases containing hovers; disclosure content releases its header plate while the header keeps active ink. Same-list gaps retain the plate. Declare ListCursor beside positioners, never as a laid-out child. `scripts/check-pointer-cursor.py` checks placement; `scripts/qml-tests/tst_disclosure.qml` checks nested hover.

### Layout

- Compose `Pane` for windows, dialogs, panels, popovers and overlays. Put titles and descriptions in its title slot, align children to its content edge and use `Inset.clearing` for rounded corners. Never add a private inset or title margin. `scripts/qml-tests/tst_pane.qml` and `scripts/test-inset.js` check shared geometry.
- Keep sticky footer padding equal and header dividers outside the body viewport. Use Pane's single edge divider; ScrollArea adds no edge line. Put pending changes in the shared footer and timed trials or mandatory confirmations in centered modals. Review holds composition.
- Show overflow with ScrollArea's fade, visible at rest, without tint or line. Keep its scrollbar in the right inset. Fit dialogs and popovers to content up to their height cap, then scroll. `scripts/qml-tests/tst_scroll.qml` and `tst_pane.qml` check shared geometry.
- Place shell windows through token-derived output geometry and the one `OverlayState.windowRoom` cap. Content beyond it scrolls. The launcher retains its own layer anchoring (owner, 2026-10-18). Resize mapped windows through compositor `placeWindow` so the top stays fixed. `scripts/smoke/app-window.sh` checks the cap.
- Animate summoned card height through `SurfaceHeight`. Flyouts retain their opening room while content fits and never shrink while shown; mask input to their cards. Panels catch outside presses across the screen. Window-anchored popups follow content. `scripts/qml-tests/tst_surfaceheight.qml` checks the shared owner; host composition remains review-held.
- Use SectionHeader for heading spacing, TabPages below tabs and shared FormRow/Field ink measurements between key/value rows. Never hand-space headings, rows or individual controls. Use `SavedSlider` for a plugin slider with a reading, except SettingField's own number control. `scripts/qml-tests/tst_section_spacing.qml` and `tst_settingfield.qml` check shared spacing. Owner authority for ink-to-ink Settings rows is Slack 1792188454.
- Preserve text-row pitch independently of glyph content and recompute adjacency when rows move. Keep the known gap explicit: no check covers a reordered SettingField. Local binding constraints belong in FormRow's code.
- Use `GroupList` for groups and its shared dividers. Give popover lists no outer inset; row padding carries the text inset. `scripts/qml-tests/tst_grouplist.qml` and `tst_overlays.qml` check them.
- Draw floating-terminal blocks through `bin/lib/tui.sh`. Leave its one blank row between blocks and below the logo; print no private blank line. `scripts/test-tui.sh` checks spacing.

### Copy

- Write user text in ASD-STE100 Simplified Technical English. State results and user actions, not diagnostic keys or internal operations. Map plugin messages to plain sentences; preserve user commands and output. Review holds wording.
- Use short action labels as icon-button tooltips. Preserve bar status readings. Help must not cover sibling labels or controls. Use shared Tooltip, FormRow and disabled-reason placement instead of local positioning. `scripts/qml-tests/tst_formrow.qml` and `tst_reasontip.qml` check clearance.
- Keep tooltip links reachable by pointer and keyboard. The source item retains keyboard ownership and only the current link draws a ring. `scripts/qml-tests/tst_tooltip.qml` checks shared interaction.
- Keep descriptions to one or two short sentences and hints to one necessary sentence. A hint adds a limit, side effect or condition, never a label restatement. Put further concise help behind InfoButton; its printable lines have no blank lines (owner, Slack 1792469888 and 1792470048). `bin/lib/check-manifests.js` checks redundant hints; review holds meaning.
- Make info help explain the setting and the user's action in new-user terms, not implementation (owner, Slack 1792182387.487899 and 1792182511.072549). A one-sentence Settings hint has no full stop; longer hints end each sentence with one (Jarvis delegated ruling, 2026-10-13). `PluginLogic.validateManifest` checks punctuation.
- Never tell users to run commands ([D061](../decisions/D061-no-manual-commands.md)). A setup step requiring the user must have a clear Settings path or the feature does not ship ([D075](../decisions/D075-consumer-features-need-no-developer-setup.md)). `scripts/check-user-commands.py` checks command text; review checks the path.
- Link user-facing page, tab and section references through the shared page-reference form. Reference a plugin's Keys section as `Settings/Keys`. Link file and folder references through `PageReference.fileReference` and the core `shell.tui.edit` route, never a private opener (owner, Slack 1792189443). Report missing-path refusals to the caller; execute no program as an open action. `scripts/test-page-reference.js` and `scripts/test-tui-logic.js` check routing; `scripts/check-user-commands.py` checks page references.
- Give user-facing limits, sizes, counts and times an info icon explaining why (owner, Slack 1792189443). Review holds it.
- Underline standalone links only on hover and links inside running text at rest and on hover. Keyboard focus uses its ring. Keep hover thickness and geometry unchanged, with a clear device row below descenders. Use shared link components, never Qt anchors or font underlining. Owner authority is Slack 1792451091 and Jarvis decisions 1792464386-2557738-17858 and 1792451829-3591639-28142. `scripts/check-design-tokens.py` checks forbidden forms; `scripts/qml-tests/tst_linktext.qml` checks drawing.

### Settings pages

- Take spacing from the shared rhythm and shared row owners. Keep switches in the label row's value column, descriptions below values and the tab strip pinned below the title while content scrolls. `settings-gap` in `scripts/check-design-tokens.py` checks gaps; review holds composition.
- Declare Settings pages through manifest schema, never plugin page code. Settings contains only values the user changes there, including editable lists and stored keys beside their setting. Keep each field in its group and common widget fields in the shared order. `PluginLogic.validateManifest` judges placement; `bin/lib/check-manifests.js` checks widget order. The Settings-only-values authority is owner Slack 1792189351.
- Keep setup actions on Setup and passive readings on Details. Declare placement rather than infer it from names. Preserve completed required steps; optional steps neither raise setup warnings nor disappear unless explicitly inapplicable. `PluginLogic.statusPlacement` and `shell/plugins/vgs.settings/Steps.js` own classification. Owner authority is Slack 1792469982.
- Give unfinished actionable steps one clear action. An unavailable step states why, what must change and the page where it changes. Never show To do with no action while a plugin is on (owner, Slack 1792182387.487899 and 1792182511.072549). `scripts/test-settings-steps.js` checks state and action consistency; review holds explanations.
- Keep all Setup actions as RowAction links. Route tool installation through the existing combined Tools notice, including a tool-blocked step's Review action. Show failed installs on the affected steps with retry and the first step's output block, never reopen the notice automatically (owner, Slack 1793683831). `scripts/test-settings-steps.js` checks states and routing.
- Derive setup-needed marks in list and tab from the same `Steps.setupNeeds` answer. Optional tools and unavailable steps raise no mark. Show a disabled plugin's page-wide state once; keep its steps' chips and hide actions except Tools Review (owner, Slack 1792637978). `scripts/qml-tests/tst_settings_setup.qml` checks the page.
- Show secrets once in masked fields using the existing keyring. Presence reports storage state, never credential validity. Keep Settings key lists beside their field, Setup keys under their step and Details keys as readings. `Steps.js` owns the words and state; `scripts/test-settings-steps.js` checks them.
- Offer presets or runtime choices instead of library format syntax and judge values before writing. Use same-plugin `choices` with stable ids. Preserve unavailable saved choices, and use a placeholder when unset means no choice. `PluginLogic.validateManifest` and `scripts/test-setting-values.js` check declarations and values.
- Use declared `addChoice` and preview actions for discovery and previews. They choose no value. Start work caused by a setting only from the user's own page choice, never config reads, reloads or migrations ([VGS-1953](https://linear.app/vanillagreen/issue/VGS-1953), ruling 7). `scripts/test-plugin-status.js` checks handlers; `scripts/qml-tests/tst_settingfield.qml` checks controls.
- Use grouped enums for the schema's supported small set of option groups. Keep selection and label wrapping in SettingField. Labels never elide and must fit the default label column; extra explanation goes in tooltip or info. `PluginLogic.validateManifest` and `scripts/qml-tests/tst_settingfield.qml` check those contracts.
- Use RowAction after a key/value reading and RowActions for several actions, never boxed buttons. Keep published row lists passive with independently focusable actions. Mark danger with a distinct icon as well as colour: trash alone only at the end of the row being removed, trash before other remove text, and an appropriate mark for non-removing danger. Place no icon-only control alone on a line (owner, Slack 1792184728 and 1792452164). `scripts/qml-tests/tst_rowaction.qml` and `tst_settings_rows.qml` check shared controls.
- Use shared BindField and ShortcutField for key editing, hints and icon states. Keep explanation over a hint only when it fits; otherwise use the info dialog. `scripts/qml-tests/tst_shortcutfield.qml` checks the shared control.

### Independent tools

- Present Settings' Open through the existing normal window host, even when its content entry is a panel. Keep the declared content choice separate from its presentation. `PluginLogic.openRequest` and `summonSurface` own this choice; `scripts/test-plugin-logic.js` checks it.
- Draw no private window border or drag behavior. The compositor owns focus indication, move, tiling and close. Keep anchored bar flyouts and generic IPC summons on their declared hosts; Open is not a conversion of every unanchored panel.
- Replace an existing flyout or layer when Open requests a window, without a second instance and without discarding held work. Normal windows remain open when another window receives focus. Host lifetime review holds these boundaries.

## The canonical example

Copy `shell/Ui/controls/IconButton.qml` for a control. For a plugin-owned look, copy `shell/plugins/vgs.launcher/Appearance.js` with `Launcher.qml`.

## Revisit when

A value cannot be a token, shared input or layout owners cannot express a needed behavior, a plugin look needs another theme input, or schema cannot describe a Settings control. Revisit for content outside its inset, several simultaneous list plates, discovery beyond bounded choices or an owner change to the layout grid.

## Not governed

Theme packaging and targets belong to [themes.md](themes.md); compositor capture belongs to [hyprland.md](hyprland.md). Component contracts belong to their source headers and the vgs-plugin API. Developer logs, comments, documentation and machine-readable output remain technical; Gallery previews may name components and properties.
