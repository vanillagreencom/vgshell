# Validation

Read before changing `scripts/validate`, a row or its verdict, a row's inputs, a test's environment, the nested sandbox or its harness, a fault the smoke excuses, a budget, or a Jarvis test.

## The approach

`scripts/validate` runs the rows a change reaches, once, on the final diff: [D100](../decisions/D100-validation-selects-by-inputs.md). A row whose inputs it cannot read runs, and a reached row that passed on the inputs it has now is reused: [D117](../decisions/D117-reuse-rows-on-recorded-passes.md).

Every validation row enters one world in `scripts/smoke/gpu-fence.sh`: [D112](../decisions/D112-one-world-owns-the-test-run.md). Package and nix use their own containers; the world's control runs outside the boundary it tests. The world owns the run root, bounds writes and hides the live session. The harness builds its own Hyprland inside it. A Jarvis suite also enters `jarvis_env_run`. The Jarvis self-test declares its account, filtered bus and network exceptions at entry. The engine publication row declares network access while retaining the world. No process a nested run starts opens an amdgpu node: [D099](../decisions/D099-no-amdgpu-node-in-validation-runs.md).

A check that could not run says so, and that is never a pass: exit 77 in [AGENTS.md](../../AGENTS.md) § Commands. A sandbox fault excuses only a reading the sandbox can spoil. A budget stands beside the run that measured it.

## Why

Only selection cuts the time a fix round costs. A row that runs when it cannot prove it is unaffected keeps the coverage a skipped row would silently lose. A run cut off at its bound loses every row it ended unless their results outlive it.

Stand-ins alone cannot bound a run. A missing stand-in can expose a host command, and a cleanup target can name the checkout. The world makes the host read-only, hides session sockets and the network, and gives one owner the run's temporary trees. Authentication stand-ins still refuse privileged steps.

Rows share one sandbox until a fatal Bash error ends its world. A row that leaves state changes what a later row reads, so a scoped run and a full run disagree. A wait on time passes on a fast machine and fails on a loaded one. A command that fails outside every check loses every later check in its row; a fatal expansion also requires rebuilding the world before independent rows can continue.

A broken environment that reads as a pass hides the regression the check exists to catch. A ceiling without its measurement cannot be judged when it fails, and a reading without its CPU pressure cannot be compared with another run.

## Rules

### Selection

- Do select only text checks for a readable diff whose every changed file is Markdown or text, including text the product displays: [D100](../decisions/D100-validation-selects-by-inputs.md). An existing QML or JavaScript file under `shell/` also takes this grant when `scripts/qml_source.py` `blank_comments` proves that only ordinary comments changed: [D124](../decisions/D124-comment-only-validation-selection.md). Code, literal contents and code whitespace stay identical, including behavior-changing inline block-comment line terminators. Quickshell `//@ pragma` engine directives remain code. Such source changes also select the keyboard, pointer-cursor and smoke edit-needle checks. Changed `// keyboard-path:`, `// pointer-cursor-exempt:` or `// focus-indicator:` directives, added, removed, renamed or unreadable source files, fixture QML, self-reading JavaScript tests and other mixed changes keep input-based selection. An explicit QML run keeps source input-based selection; an explicit full or release run keeps every check. `scripts/validate` owns classification, and `scripts/test-validate.sh` holds the grants and exclusions.
- Never anchor a smoke edit in a QML or JavaScript comment or repeat its needle in a comment. `scripts/check-smoke-needles.py` follows static literal, variable, array and heredoc values into `edit_tree` and `plugin_control`, including every argument group in a supported shifted loop. It also reads literal match-once needles in the shared harness, tree helper and every row's inline Python. An unresolved Bash edit refuses the check. An inline edit dependency that the literal reader cannot resolve retains input-based selection through its producing row and the existing input reach; an unreadable dependency reading retains input-based selection. `scripts/qml_source.py` owns comment recognition for both selection and the needle check.
- Do declare every file a row reads itself, its plugin entry files, fixtures and scripts, and the file of every row whose functions or state it uses, on its input line in the form [scripts/AGENTS.md](../../scripts/AGENTS.md) gives. An undeclared read skips the row on a change that breaks it. The `smoke rows name the rows they read` row of `validate tools` refuses a function or variable read from an undeclared row.
- Do let selection count every shell file a declared file loads statically, directly or through other files; a line need not name them. Selection reads a type the file names that its own directory holds or exports through a `qmldir`, or that a module it imports as `qs.<Dir>` or a directory it imports by relative path does, each `qmldir` that lookup consults, and a file it imports by relative path with `import` or `.import`. Stateless JavaScript libraries and scripts with imports have no implicit QML directory imports. The reading matches words over comment-free text, strings included, except import declarations and their shadowing namespace names. A match too wide adds a row and never skips one. A function-local JavaScript hunk narrows its explicit namespace import edges to those that name the changed functions or their local callers. A namespace passed as a value or indexed by data, an unattributable hunk or a non-namespace load keeps whole-file reach. Direct row inputs still observe the whole declared file, and an observing importer retains conservative transitive file reach. A shell file the reading cannot read, a reading that fails, or a removed `.qml`, `.js` or `qmldir` file under `shell/` or `scripts/smoke/`, whose former loaders the reading cannot see, runs every row with one `validate: smoke-rows=all reason=qml-load...` line. `scripts/test-validate.sh` holds load reach and function observation.
- Do trace a shared harness input's function-level hunks through their callers to the rows that reach them, including the rows those rows read, through `scripts/validate`'s existing shell reader. Both sides of every hunk must be attributable. Quoted callback names and generated helpers count as uses. A top-level use, a top-level hunk or an unreadable function-level reading selects every row; no separate row map decides reach. `scripts/test-validate.sh` holds a real row, an indirect helper, and the full-area controls.
- Never put a product file on the input line of `scripts/smoke/harness.sh`. That line declares shared harness inputs, not product dependencies. Review holds it.
- Do compare a restack against the last validated commit. Intersect incoming reach with the branch's selected inputs through the same selection indexes, including dependencies the branch did not edit. Unrelated incoming changes select no product check; a reached input selects only its reached rows within that intersection, plus the core rows and dependencies. An unreadable reach selects the full area. Repository checks still run except under the text-only rule above. `scripts/test-validate.sh` holds a real row through incoming helper, core, unrelated and branch-fix commits.
- Do let a changed path in a mixed or non-text diff select the nested smoke and every smoke row whose input line names it, even where another `scripts/validate` table row owns that path and the nested smoke row's own inputs do not name it. `scripts/test-validate.sh` holds a `scripts/fixtures/vpn/*` file the `VPN decisions` row owns selecting the row that names it.
- Never add a `repo` row for a check a path pattern can select; a `repo` row runs on every change except under the text-only rule above. Review holds it.
- Never leave a row out of a scoped run without a line that names it. `scripts/test-validate.sh` holds the lines a scoped run prints.
- Never let a time figure remove a row the change reaches: neither a row's median nor a lane's run time removes it, and the batch run on main still runs every row once more. `scripts/test-validate.sh` holds a reached row with a long median staying selected.
- Do reuse a selected row that passed on the inputs it has now, as selection names them, instead of running it again, and name it in a `validate: reused` line: [D117](../decisions/D117-reuse-rows-on-recorded-passes.md). A row records its result as it ends, so a run cut off at its bound keeps what its ended rows proved. A record binds the inputs the row's line names, and for a smoke row the shell files those load, that differ from the branch point; a smoke row's binds those of every row it reads too, and only a row whose `%scope` input says it reads the change base binds the base and the scope. The nested smoke row records no pass of its own: when selected it runs, with the core smoke rows and every smoke row whose line cannot select, and each other smoke row is reused on its own record. A repo row and a row with a `$NAME` or `device:` input always run, and `--full` reruns every row. A run that reaches its exit, after a TERM, INT, HUP or QUIT too, withdraws its records when its tree changed while it ran; a KILL leaves its ended rows' records on the tree it read at its start. Validate keeps each smoke run's completion records, removes its row journals once read, and keeps the newest three such runs. `scripts/test-validate.sh` holds reuse after a cut, a rerun for each input a record binds and the nested smoke running whenever it is selected.
- Do let a smoke row's pass stand on its attempt's judge readings, not on a judge row that ran after it. `harness.sh` reads, through the predicates `rows/auth-sentinel.sh` and `rows/tui-guard.sh` share, the authentication calls, the stand-in terminal's refusals of a script no shipped plugin holds, and whether each sentinel and the stand-in terminal is still the harness's own and found first, at each row's start and end and once more as the attempt's teardown ends it. `smoke_outcomes` in `scripts/smoke/row-inputs.sh`, the one reader of a smoke run's per-row records, proves no pass of an attempt that failed outside every row; whose judge row failed or left a check unmeasured, whether it ended or not; or whose readings show a sentinel or the stand-in changed, or a call or such a refusal anywhere but between the start and end readings of the judge row whose own controls plant it. It proves no pass of a row with no end reading. A call a row's background process makes after the row ended lands in a later window, so it voids the attempt, not one row. The closing reading is required, and it excuses no field: a judge row cut before its end reading may not have counted what changed in its window, so any change the closing reading shows voids the attempt. An attempt with no closing reading proves no pass, since what its rows' processes did after its last row reading is not seen. A unit's stop, as `dev-validate-run` ends a run at its bound, TERMs every process of the world at once, the pipes the teardown writes through included; the world's bubblewrap monitor ignores it and the teardown outlives a dead reader of its output, so it takes the closing reading before the namespace ends. A world killed before its teardown leaves none. The readings do not cover the fixture index `tui-guard` reads. `scripts/test-smoke-verdict.sh` holds the real readings against that judgement and an attempt with no closing reading, `scripts/test-qml-smoke.sh` a unit's stop mid-row through the real driver, world and teardown, and `scripts/test-validate.sh` the reuse that follows it.

### Plugin inputs

- Do name the plugin files a row loads on its input line, never the plugin's folder. A file the row's shell never builds cannot change the row's reading, and a folder input runs the row for every file in it. Selection adds the files a named file loads statically, as § Selection says, even one it builds only for some pages: the Settings `PluginPage.qml` names `StatusLine.qml`, `KeyField.qml`, `RowsList.qml` and `ListField.qml`, so a change to any of them runs every row that names `PluginPage.qml`. `scripts/test-validate.sh` holds the selection over a real row's input line.
- Do name the files of the plugin's entry points that the row reaches itself, such as a service the row calls over IPC or a widget it reads. A started shell loads every always-on entry point for every row, and the core rows cover it.
- Do keep `manifest.json` where the row loads the plugin at all. The core reads it to build each surface.
- Keep the plugin folder where the row reads the plugin as a whole or its loads cannot be read, such as a row that opens pages by a variable it computes: [D100](../decisions/D100-validation-selects-by-inputs.md) runs a row whose inputs it cannot read. Review holds it.
- Gap: selection does not read a load a value computed at run time chooses, such as a `Loader` source built in code or a Settings page a manifest selects; the row's line names it. Review holds it.

### Test isolation

- Do run every check through the row runner in `scripts/validate`. The world gives each row its own home, XDG directories and scratch root, and removes them after the row. Package and nix use their own containers; `scripts/test-gpu-fence.sh` runs outside the world to test its boundary. Selection, last-pass and row records stay in validate's own process; the nested smoke's driver, outside its world, writes its per-row results only in the directory validate names it. `scripts/test-validate.sh` holds it.
- Do select the live engine publication check for a floor or engine recipe change. Its explicit `network` row owner enables the world's network only for that operation; `offline` excludes it and keeps its process-boundary controls. Keep the default packaging judge offline so publication can run before availability. `scripts/test-validate.sh` holds selection and the declaration.
- Do run the installed-engine prerequisite synchronously before a selected nested entry, including an explicit `scripts/validate qml`. A failure or unreadable executable prevents entry dispatch and names the fleet installation step; a parallel packaging row cannot provide that ordering. `scripts/test-validate.sh` holds the refusal before dispatch.
- Do keep scratch indexes and their new git objects under the row root. A row reads the checkout's existing objects without writing its git directory. `scripts/test-validate.sh` holds it.
- Do prepare the catalog's pinned archive listings before its offline row enters the world. `scripts/validate` calls `scripts/check-catalog-wallpaper-names.js --prepare`, whose existing downloader verifies each archive's size and SHA256, and keeps only image names at `${XDG_CACHE_HOME:-$HOME/.cache}/vgshell/validate/theme-listings/<archive-sha256>/listing.json`. The row consumes this directory through the world's read-only `--input` bind, including when the directory is under the caller's masked `/tmp`. An absent listing is an input-step failure, never an offline download or exit 77. `scripts/test-check-catalog-wallpaper-names.js`, `scripts/test-validate.sh` and `scripts/test-gpu-fence.sh` hold it.
- Do use `scripts/validate --prepare-catalog-inputs` for the same parent-owned preparation in nightly. `.github/workflows/nightly.yml` restores and saves `/home/ci/.cache/vgshell/validate/theme-listings` with a key containing the hash of `themes/catalog/index.json`; a cache miss runs the producer before offline validation. The former `.git/vgs-catalog-listings` is a rebuildable cache and has no reader or migration in the new code. The overseer retires it after every running lane has rebased past this change.
- Do run every test and sandbox process under the test-run marker `VGS_TEST_RUN=1`. `scripts/test-vgshell-reload.sh` holds the theme judge's refusal under it.
- Do give every process a test spawns an explicit environment, never the caller's whole one. Gap: no check reads a test's spawn calls.
- Do let the world set the run's home, XDG directories, private runtime, temporary directory and test marker, and pass only its declared environment table. Display identifiers and the caller's raw session bus never enter. `scripts/test-gpu-fence.sh` holds the boundary.
- Do verify the inherited world's mounts before keeping its root readable in a child world. A marker alone cannot expose the caller's temporary files or sockets. The child keeps the parent's fixtures read-only and owns its own writable root. `scripts/test-gpu-fence.sh` holds it with a planted marker and socket.
- Do show a test's stand-in files at a fixed system path through bubblewrap read-only overlays of the host directories, with a layer holding any missing mount point and a bind over it, never through a path override in the shipped script: [D107](../decisions/D107-format-change-ships-its-migration.md). The scanner's NetworkManager VPN fixtures instead change the fixed directory tuple in disposable scanner copies; the import test consumes core requirement rows. Review holds it.
- Do hand a runner that starts a compositor, the shell, `qmltestrunner` or a browser to the world before it starts anything. The world binds the host read-only, restores device access, gives `/tmp`, `/dev/shm` and the runtime private tmpfs mounts, masks the caller runtime, `/run/dbus` and `/run/tailscale`, and unshares the network. `scripts/test-gpu-fence.sh` holds it and each entry point's declarations.
- Do declare writable outputs and `--keep` at world entry. An output may not contain the checkout, its git directory or the caller's home. The world alone creates and deletes run roots: its own, and the root of a world whose owner is gone, which the next world under the same `TMPDIR` removes. The root's name carries its owner. The world never removes a root whose owner is alive, unreadable or in another PID namespace, or one kept by `--keep`. A root without an owner in its name, made by older code and a `--keep` root of that form included, is removed only when it is older than 10800 s and no process holds it as a working directory, descriptor or mount point. It reports a root it removes, cannot remove or keeps for any reason but a live owner as `cleanup=reaped`, `cleanup=rm-failed` or `cleanup=kept`, the failed one with the stderr of the failed command, on its own stderr, which is the run log. `scripts/test-gpu-fence.sh` holds it; a harness closes its recorder and processes. The harness runtime lives under a private runtime child backed by that root so evidence survives namespace teardown. `scripts/test-smoke-owner.sh` holds lifetime and cleanup.
- The owner's home remains readable by absolute path. Redirected HOME keeps tools from selecting it by default; the boundary blocks writes. SIGKILL of the world owner ends its namespace and leaves its root because no trap runs; the next world reaps it.
- Do run every QML test in the shell's garbage collector mode. `scripts/qml-unit.sh` applies each `//@ pragma Env QV4_*` line of `shell/shell.qml` to every `qmltestrunner` start, so the value has one home. `scripts/test-qml-unit.sh` holds it.
- Never let a QML test log a warning it does not declare. `scripts/qml-unit.sh` fails an undeclared log, and its header gives the declaration.
- Never count a mutant as killed on any status but a failed test. `scripts/test-qml-unit.sh` holds it.

### Host safety

- Never authenticate, and never run a real PAM, polkit, sudo, faillock or keyring step; the one exception is the stored key the Jarvis self-test reads under its rules below. The core row `scripts/smoke/rows/auth-sentinel.sh` and `scripts/sandbox-shots.sh` fail a run that reached an authentication stand-in, and a smoke pass from a run cut off or killed before that row is reused only on judge readings that show no such call (§ Selection).
- Never let the stand-in terminal run a shipped plugin's TUI script; it runs a fixture copy. `scripts/check-smoke-terminal.py` refuses a row that writes its own, and `scripts/smoke/rows/tui-guard.sh` checks the stand-in at the end of a run; a smoke pass from a run cut off or killed before that row is reused only on judge readings that show no such refusal (§ Selection).
- Do assert the argv a stand-in recorded, never the effect of the script it stands in for. Review holds it.
- Never add a device fake or a device-command stand-in in a row; `scripts/smoke/devices.sh` owns them. Review holds it.
- Do hide every stand-in registry name from the shell's host PATH in both smoke and capture runs. Removing a stand-in must resolve to `none`. `scripts/test-sandbox-shots.sh` holds it.
- Never expose a command from the invoking user's home on the shell's host PATH. A per-user install or shim there can install on use, and the shell runs `--version` on each command a requirement names. A row that needs such a command writes its own stand-in, and `scripts/jarvis-selftest.sh` links its selected brain program into the harness's command shim. `scripts/test-sandbox-shots.sh` holds it.
- Do start a device row behind the guard in `scripts/smoke/devices.sh`, which records the row not measured when it reads a leak to the host. `scripts/smoke/rows/device-fakes.sh` holds the guard.
- Do capture the sandbox only through `scripts/smoke/shot.sh`, which refuses a socket outside the sandbox's runtime dir and an output outside `tmp/`. `scripts/test-sandbox-shots.sh` holds it.
- Never reach the host compositor from a run: the sandbox reads, dispatches to and draws on no live session. Review holds it.
- Do run every input tool, `wtype`, `$sandbox/click`, `$sandbox/keyboard` and `wl-copy`, only after `nested_input_check` in `scripts/smoke/harness.sh`. It refuses, with no tool call, an environment that does not name the socket the harness started. `scripts/test-smoke-input-guard.sh` holds it for each helper that runs one.
- Never return a secret, or data derived from one, from a sandbox reader; a reader returns state and geometry. Review holds it.
- Never hold the shared sandbox slot gate above its load limit with a lane's own stress load. A proof under load runs once, with the smallest load that reproduces the failure, inside the lane's own slot run, and a Done-when never asks for repeated load runs. Review holds it.

### Screenshot baselines

- Do use `scripts/sandbox-shots.sh`'s baseline pair for the UI review's before and after captures. Use the same harness script for both runs; change only the product tree with `--rev`. The script hash binds both sides, so two revisions of the script are not a pair.
- Do complete one measured before run against main with a fresh ledger. Only failed assertions over successful observations become omissions. The normal closing verdict seals the ledger's bytes and script hash, including an empty ledger. An interrupted, failed-operation or unmeasured run supplies no sealed baseline.
- Do accept an after omission only when scene, mode, check label, got and want match the sealed before record exactly. A changed got or want is a new failure. Normalize only retained, acquired world and harness roots; preserve product values and identities whose ownership cannot be proved.
- Never record or excuse planted scene controls, operation acknowledgements, failed commands, IPC timeouts, reader failures or safety checks. A poll whose successful final observation differs from its expectation is an assertion; a failed read or timeout is not.
- Never use a changed, unsealed, unreadable or wrong-script ledger. `scripts/test-sandbox-shots.sh` holds the pair, empty ledger, integrity and failure exclusions through the production assertion boundary.

### Nested sandbox

- Do start and stop the sandbox only through `scripts/smoke/harness.sh`. `scripts/test-smoke-teardown.sh` holds the teardown.
- Do draw the nested compositor to the harness's own sink compositor, `scripts/smoke/sink/sink.c`, which the harness starts in the GPU fence before the compositor and stops with it. The sandbox needs no host display or lit monitor and puts no window on the live desktop: the sink configures each output once, at 1920x1080, sends no input, and paces frames at its own 60 Hz. `scripts/test-smoke-sink.sh` holds the sink.
- Do retain a failed or interrupted row's shell instance logs, nested compositor logs, row output, the span of the sandbox's `ipc.log` written between its first and last leak readings (to the end for an interrupted row) and probe dumps after its namespace ends and before the world removes its root. The world is the sole copier, including after a killed runner. `scripts/smoke/evidence.py` owns the retained set: at most 1 MiB per file and 8 MiB per row including its index. Ordinary logs keep their final span; ANR evidence keeps its frozen observation span. Copies land in `smoke-evidence-<sandbox>/<row>/` at the output declared on entry: beside the redirected run log, under `tmp/qml-smoke/` for a terminal run, or in `qml-smoke.sh --log-dir`. The resume driver writes bookkeeping only in exclusively acquired scratch, prints each attempt's path, and retains its completion authority and bookkeeping for every managed run. Passing rows retain no row evidence. Each frozen boundary reading registers before a terminal restoration exit and keeps the nested wallpaper-state file's existence, exact bytes within the file cap, or unavailable cause. This is advisory evidence, independent of the required leak classes and their verdict; it reads no caller state and changes no restoration target. Frozen ANR spans retain priority, then boundary readings, then ordinary log tails. A copy failure reports its cause and preserves the run's verdict. `scripts/test-smoke-evidence.py` holds it.
- Do wait on a state the shell or the compositor reports, never on time. Review holds it.
- Do print each check's elapsed interval, its outcome and its row in the row log. The interval includes actions and setup since the previous check report, not only the final read. Print world start, harness start, each shell start and teardown separately. These readings change no verdict. `scripts/test-smoke-dumps.py` holds check reporting; review holds cost attribution.
- Do bound each smoke IPC call at 10 seconds in `scripts/smoke/harness.sh::ipc_call_last`. Expiry kills the call and fails its row as an operation failure, with the target, function and bound. `scripts/test-smoke-dumps.py` holds it, including a reader that catches the failure and a paged reply.
- Do keep the nested compositor's not-responding dialog enabled. The display recorder latches its appearance, including a dialog that closes before row end. `smoke_row` fails that row under `anr-dialog` and freezes its original leaks before the one boundary restoration removes a dialog proved to belong to that nested compositor. A dialog already mapped at entry remains part of the literal start; cleanup cannot subtract it or invent an earlier focus. An unrecoverable entry ends that world. Hyprland detaches its dialog, and the public client record exposes no launch owner. The recorder matches the dialog's stdout pipe to its read end in the bound compositor generation through Linux `/proc` descriptors. A pidfd binds cleanup to the acquired process. An unproved owner or failed cleanup remains a failure. `scripts/test-smoke-anr.py` holds row attribution, detached ownership, cleanup and continuation.
- Do freeze bounded compositor spans when the recorder observes a dialog, before later rows overwrite the retained tail. The failed-row copier prioritizes these spans within its existing caps. Record missing or clipped sources and observation times explicitly; a receipt time is no missed-ping timestamp. A span alone cannot distinguish host load from a shell stall. `scripts/test-smoke-evidence.py` holds retention; review holds causal claims.
- Never call the focused client the unresponsive target. Hyprland's dialog exposes target title and class but no target PID. A unique matching client is an inference; otherwise target attribution is unavailable. Preserve that limit beside the failure. A dialog between rows belongs to the next observed boundary. Removing it excuses no stale client, layer or other failed check. `scripts/test-smoke-anr.py` holds ambiguous and unavailable attribution.
- Never let a reader raise; answer a state word for absent, partial, missing or empty input. `scripts/check-smoke-readers.py` refuses a reader outside `py_reply`, and the harness fails a row on any Python traceback.
- Do name every error line a row provokes in `expected_errors`; `smoke_row` empties the list at each top-level row and fails that row on every other error line the shell logged from where the row before it stopped reading to the end of its restoration, including the whole log of a shell the row replaced and, for the first row, the shell's start. A shell the harness starts outside any row boots before the next row's window opens, and a line the shell logs after a row's last read belongs to the next row. A row run inside another keeps the outer row's list and window. `scripts/smoke/rows/updates.sh` holds the controls.
- Do let a failed command outside every check end only its row. `smoke_row` in `scripts/smoke/harness.sh` fails the row with the status and runs the next row; a restoration whose post reading still differs ends the run with the original status. `scripts/smoke/rows/updates.sh` holds it.
- Do contain a fatal Bash expansion, including an unbound variable or invalid arithmetic, at the existing `qml-smoke.sh` world entry. Attribute the open row with its status and Bash's native variable or expression and source line, await EXIT and namespace teardown, then run independent remaining rows in a fresh world through the existing `--rows` dependency closure. Count each target once; core and producer replays rebuild state. Never replay a known-fatal producer: list each dependent target as a blocked failure naming that producer and its diagnostic. A fatal core row therefore blocks every remaining target and ends the run. Fatal and blocked results always keep validation red. Resumes consume remaining targets rather than using a time limit. `scripts/test-qml-smoke.sh` holds continuation, attribution, dependency blocking and the control without resumption.
- Do let the ordinary public driver publish each managed attempt's immutable `completion.json` only after the world releases its namespace and both fence and log-reader joins finish. Its first accepted stop determines that open attempt's requested status and interrupted reason. The recorder holds local world and collection facts that refer to this authority; its completeness judge remains the only collection judge. After an attempt seals, a stop cancels only the open aggregate run and prevents another launch. After the final run seal, later signals cannot change the frozen result or public exit. Keep the driver directory and its run `completion.json` readable after every exit, including success. Missing required input or failed publication cannot yield an authoritative passing record. Native direct, first-bar and shader entries retain their own local contract. `scripts/test-qml-smoke.sh` holds the managed cutoff and required records.
- Do keep restoration of a failed row whose harness process remains alive in `smoke_row`; fatal expansion recovery belongs to the entry's fresh world. Keep `read_count` and `scripts/check-smoke-readers.py` as hygiene so rows can finish their own checks and cleanup without a restart.
- Do establish or name every precondition a row reads, and wait on the reported state. Review holds this rule; the leak check's plugin enablement and session-bus owner classes instrument changes to those preconditions.
- Do start `vgs.themes` disabled in the harness seed: a row's theme apply writes a selection that an enabled Themes would draw into every later layers reading, so a row that reads Themes enables it when it starts. `scripts/smoke/rows/leak-check.sh` holds the seed.
- Do fail every shell crash a row does not expect. Only `scripts/smoke/rows/child-lifetime.sh` expects one: it declares the process before crashing it, consumes exactly that process's one report, and closes only a reporter window the recorder proves it owns; zero reports, another or an unproved reporter fails the row, and the row's control holds a declared crash that never happens.
- Know that a full restore after a failed `hyprland-consent` row brings back its unwired `hyprland.lua` while the welcome-seen marker stays, so the next layer write asks for consent again and one failure there ends the run, until [VGS-2118](https://linear.app/vanillagreen/issue/VGS-2118) restores a row's start world as one set.

## The canonical example

`scripts/smoke/rows/supervise.sh`: one input line, its ceiling beside the run that set it, a wait on reported state before each read, and a control for each rule. Copy it for a new row.

## Revisit when

CI gains a runner with a DRM render node, the sandbox gains its own PAM, polkit and session, a check needs host state the sandbox cannot reproduce, the reference machine changes, or a regression lands that an unselected row would have caught.

## Not governed

What a row or a Jarvis suite asserts, which is its own header; the input line format, which is `scripts/AGENTS.md`; the row order, which is `scripts/smoke/rows.list`; the harness's helpers, which are `scripts/smoke/harness.sh`.

Nightly container-build reuse reads its input hash from `scripts/validate --input-hash`, never a separate input list. Keep its passing record in the Actions cache and look it up without restoring files. The latest passing build must match the inputs and be less than seven days old; a weekly or manually forced full build still checks upstream drift. Review holds the workflow wiring; `scripts/test-nightly-cache.py` holds the age and force decisions.
