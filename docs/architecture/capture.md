# Capture

Covers: shell/plugins/vgs.capture/**, scripts/test-capture.py, scripts/smoke/rows/capture.sh, scripts/smoke/fixtures/capture/**

The Capture service owns each action's worker and every tool the worker starts. The widget and panel read plugin status and ask the service through [plugin IPC](../../shell/Core/IpcRegistry.qml). Neither surface starts a capture or writes configuration itself. The launcher sends area capture to that same service.

- The service matches `Hyprland.focusedMonitor.name` to an enabled output from the [monitors capability](hyprland-monitors.md). Only that output's name reaches `grim -o`. The worker never selects an output by itself.
- Every tool the worker starts gets a standard input at end of file unless it needs a pipe. The worker's own standard input is the service's control pipe, which stays open. slurp reads predefined boxes from a standard input that is not a terminal until end of file, before it maps any surface, so an inherited pipe held it with nothing drawn.
- Area screenshot, recording and text capture share one selection. `hyprpicker -r -z -d -q` freezes every output first; slurp maps after it, so slurp stays on top and takes the pointer and keys. slurp keeps its default white wash, which shows on a dark desktop where a dark dim does not. After the selection the worker captures the box, scaled down, until two captures agree: Hyprland fades slurp's layer out after it exits, and over the still freeze that fade is the only change. A screenshot or text capture reads the frozen frame; the freeze ends before the recorder starts and when the action ends, even while the worker holds the clipboard.
- Escape, which slurp answers `selection cancelled`, and a second press of the same key cancel. The service writes `cancel` to the worker, which ends slurp; stdin end of file cancels too. Neither posts a notice or creates a file. A press of another capture key while one runs answers busy.
- The worker reads XDG user-directory values as quoted data. It never sources the user-directory file. Each capture reserves a distinct private file. Selection cancellation happens before any file or folder is created.
- The worker streams the selected PNG to Tesseract. Empty recognized text never reaches the clipboard. Status contains no recognized text or clipboard bytes. The CLI has no structured model-load failure; `--list-langs` lists files without proving they load. The worker maps the [upstream English-model failure](https://github.com/tesseract-ocr/tesseract/blob/main/src/ccmain/tessedit.cpp) to the error reason `english-data-unavailable`. The service shows its existing error notice with a plain missing or unreadable data message. Other tool failures keep their own cause.
- Clipboard copying uses `wl-copy --foreground`. Its worker stays a child of the service after the action finishes, until another copy replaces the clipboard. A new action starts an independent worker. This keeps clipboard delivery available without a detached provider.
- Recording status becomes active only after the recorder writes the reserved file. The worker sends SIGINT to its own recorder on stop. The service keeps its recording indicator through finalization. Normal stop and SIGTERM teardown wait for owned children. A tool that ignores its stop signal is killed and never reported saved.
- A fresh Python interpreter sets each tool's Linux parent-death signal before exec: SIGINT for the recorder and SIGTERM for other tools. A parent check closes the fork-to-registration race. This also handles Quickshell's SIGKILL of a destroyed worker. The launcher uses no `preexec_fn` or threads.
- Capture commands are required because the plugin presents their actions. Missing commands disable their actions and remain repairable through the [core requirement notice](requirement-notice.md). Package dependencies install the command packages and the English text data declared in `packaging/runtime-libraries.json`. The command-only notice cannot repair missing English data when Tesseract is already present. [The recipe check](distribution.md#recipe-check) records channel package gaps.

## Evidence

`scripts/test-capture.py` drives the worker against tool stand-ins. It holds the control pipe open as the service does. It checks output selection, identical clipboard bytes, geometry, cancellation by slurp, Escape and a second press, no selector or freeze left behind, freeze failure, empty OCR, tool errors, missing English data, XDG folders, recording finalization and teardown. It kills the recorder and clipboard workers to read their children's stop signals. Its controls remove OCR error classification, output selection, clipboard copying, the closed tool stdin, the freeze stop and parent-death signals, and replace SIGINT with SIGKILL. The fade wait has no control: a stand-in draws no fade. It rests on a reading on host cachy on 2026-10-04: grim of a region right after slurp exited read the dim, 50 ms later part of it, 150 ms later none.

`scripts/smoke/rows/capture.sh` reads the service, widget and panel in the nested sandbox. grim runs as the real tool on the nested socket. For the area it also runs the real slurp and hyprpicker: the selection maps above the freeze, a drag saves and copies the box, Escape and a second press cancel, and none leaves a slurp or hyprpicker process. A disposable helper copy that lets slurp inherit the control pipe fails the selection reading; disabling the plugin then ends that held selection with no slurp or hyprpicker left. PNG dimensions come from Hyprland's output mode. Its disposable helper copies drop output selection, clipboard copying and graceful recording stop. Each copy runs through service IPC and fails the same PNG or recording readback that passes the original. The row holds recorder finalization to read the active indicator, reads that no recorder remains after the stop, stops a second recording through a widget click, and reads clipboard-provider release on disable. It also reads the core notice after Tesseract is hidden from the shell's PATH.

## Omarchy and tool interfaces

Omarchy uses Slurp, Tesseract, wl-copy and SIGINT recording stop. VGS uses these interfaces with the plugin service as the process owner. Omarchy's screenshots use its own omasnap package. VGS calls grim because Fedora also supplies it. Omarchy's `omarchy-capture-region` and `omarchy-capture-text` freeze with `hyprpicker -r -z` under slurp, as VGS does. Omarchy's Hyprland configuration turns off animation for slurp's `selection` layer; a plugin's layer rules name only `vgs:` layers, so VGS waits out the fade instead. VGS omits annotation and webcam capture.

The [Arch recorder manual](https://man.archlinux.org/man/gpu-screen-recorder.1.en) documents `-w region -region WxH+X+Y`. VGS sends Slurp's logical coordinates in that form. Omarchy's compact `-w WxH+X+Y` differs from the documented Arch interface. The [Quickshell process reference](https://quickshell.org/docs/v0.3.1/types/Quickshell.Io/Process/) defines the worker lifetime and stdin stop route. The [Hyprland reference](https://quickshell.org/docs/v0.3.1/types/Quickshell.Hyprland/Hyprland/) supplies the focused monitor. The [Linux parent-death signal](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html) keeps ordinary exec children owned after a destroyed helper. The [Python subprocess reference](https://docs.python.org/3/library/subprocess.html) explains why the launcher avoids `preexec_fn`.
