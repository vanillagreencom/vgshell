# D129: The VPN kill switch is an nftables table that systemd re-applies from a user-owned "meant on" file

[← Decision Index](INDEX.md)

**Date**: 2026-11-08

**Status**: Active

**Research**: [VGS-2397](https://linear.app/vanillagreen/issue/VGS-2397): owner ask relayed by Jarvis, 2026-11-08; the design and owner sheet attached to the issue; owner approval, Slack message 1794203722.881669, 2026-11-08.

**Refines**: [D110](D110-tailscale-and-vpn-split.md), for `vgs.vpn`: the plugin gains one system step and writes one state file outside NetworkManager. It still edits no profile.

**Decision**: While a VPN is meant on and its kill switch is on, an nftables table, `inet vgshell_kill_switch`, refuses and counts every IPv4 and IPv6 packet that leaves or is forwarded out of any interface other than the tunnel. It passes loopback, the tunnel interface, `tailscale0` and packets Tailscale marks (`0x80000/0xff0000`), UDP to the WireGuard peer endpoints, DHCPv4, DHCPv6 and IPv6 neighbour discovery. Forwarded replies a tunnel brings back also pass, so containers and virtual machines that route through the tunnel keep working. With the local-network allowance on, it also passes private, link-local and multicast addresses, except DNS on ports 53 and 853. While a sign-in page is open, it also passes DNS, HTTP and HTTPS for at most five minutes, through set elements the kernel expires. "Meant on" is `/var/lib/vgshell/vpn/state`, a file the user owns. The shell writes it when the user turns a profile on or off in VGS, and `vgs-kill-switch off` clears it with the shell stopped. One `bin/vgshell-system` row, `vpn-kill-switch`, installs the root script `/usr/local/bin/vgs-kill-switch` and four systemd units. A path unit runs `vgs-kill-switch sync` when the state file or a NetworkManager profile changes. A oneshot runs it at boot before `network-pre.target`. A socket-activated unit answers the armed state and drop count to any local user. The sync reads the state file with the owner's credentials, reads the profile's interface name and peer endpoints through `nmcli`, and changes only rules and set elements, so the table and its counter survive each change. It covers WireGuard profiles whose endpoints are IP addresses. Any other profile reads the kill switch as unavailable, with the reason.

**Why**: The block must hold with the shell stopped, across reboot and wake, and while the tunnel is down. Only a kernel rule loaded by system units holds in all of those states, and nftables is the kernel firewall ufw already runs on here. A separate table coexists with ufw without changes to its rules: every base chain on a hook runs, so this table's refusal holds whatever ufw accepts, and ufw never flushes a table it does not own. The user must turn the switch on and off with no password, so "meant on" is a file the user writes and a root unit reads. NetworkManager's dispatcher cannot be the trigger, because turning a VPN off while its tunnel is already down changes no device and runs no hook. `nmcli` cannot write a profile's user data, and changing a profile would break D110's "It edits no profile". Refusal, not a silent drop, makes an application fail at once and fall back to IPv4. This matters because px13's Nord profile carries IPv4 only, so IPv6 to the internet is refused even while the tunnel is up.

**Rejected**: Nord's own app, `nordvpnd`, which Omarchy installs. It is a closed root daemon with its own account sign-in. It covers Nord only and keeps its own interface outside NetworkManager, where `vgs.vpn` cannot show or control it. ufw rules, because ufw holds the user's own rules, each change needs root, and `ufw reset` removes rules it holds. `nftables.service`, because Arch's `/etc/nftables.conf` flushes the whole ruleset, ufw's tables included. A NetworkManager dispatcher hook as the only trigger, because it misses an off press while the tunnel is down. A VGS daemon or poller, because the requirements forbid one and systemd's path and socket units already hold the need.

**Revisit when**: The owner needs a kill switch for an OpenVPN or other non-WireGuard profile, or a WireGuard endpoint that is a host name. Also when NetworkManager gains its own kill switch, ufw or Arch stops using nftables, or the sign-in page needs passage scoped to one browser.
