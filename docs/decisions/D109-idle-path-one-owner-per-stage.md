# D109: The idle path has one owner per stage, each on its own idle watch, and vgs.power owns energy

[← Decision Index](INDEX.md)

**Date**: 2026-10-18

**Status**: Active

**Research**: [VGS-1897](https://linear.app/vanillagreen/issue/VGS-1897): the Omarchy study (quattro at `b5f8593d`) and the comparison on that issue; [VGS-1895](https://linear.app/vanillagreen/issue/VGS-1895): the Hyprland 0.56.2 trace of idle notifications reset on window events; [VGS-2087](https://linear.app/vanillagreen/issue/VGS-2087): the accepted secure-cover design, built in [VGS-2097](https://linear.app/vanillagreen/issue/VGS-2097).

**Refines**: [D062](D062-native-lock-and-polkit-plugins.md), for the core `idle` capability: it serves every stage of the idle path, not the lock alone. [D081](D081-system-steps-closed-core-table.md), for the step table: a step may take one value from a closed set its row in `bin/vgshell-system` names, the one owner of that set, judged before any root command runs.

**Decision**: Each stage of the idle path has one owner, with its own watch on the core `IdleRegistry`: dim in `vgs.displays`, the screensaver in `vgs.screensaver`, the lock and the lock before sleep in `vgs.lock`, and display off, sleep after idle, the wake from sleep, the session's Sleep and Hibernate launcher rows, the power button and lid actions, wake sources, Wake on LAN and disk sleep in `vgs.power`, which keeps its id. No owner reads another owner's setting; a plugin declares its stage in its manifest, and the core lends the stages and their order as one read-only record. VGS changes panel power with one global DPMS request through a core dispatcher, lets Hyprland's input options wake the panels, and sends DPMS on only at a wake from sleep. The core lends that the panels are off, and the screensaver stops on it. Sleep goes through logind and defaults to Never. Every watch keeps `respectInhibitors: true`, and VGS accepts that Hyprland restarts those watches when a window maps, unmaps or takes focus. Only the idle source, dim, screensaver, lock and lock before sleep exist in code at this date; `docs/architecture/power.md` names the item that adds each other part.

The screensaver and the lock each take their stage's own watch from the core. Each idle notification of that watch carries a ticket that proves the core saw the seat go idle. An idle lock that finds the screensaver running keeps it, held inside the secure lock surface, and the first input ends it. Equal positive Lock and Screensaver times are one exception: the lock's own idle event starts the screensaver inside the lock even when the screensaver's watch, created later, would notify after it. That changes only when the screensaver appears. No stage's saved time, no watch's creation baseline and no lock deadline moves, and an edit of one stage never recreates another stage's watch. Manual, sleep and restore locks always show the lock screen.

**Why**: The VGS screensaver and lock are layer surfaces, which do not restart a watch, so separate watches stay correct with no cycle state; Omarchy's one monitor and timers exist because its screensaver is a window. The owner asked for the running screensaver to stay over the idle lock (VGS-2087). Two watches with equal times can notify in either order when one was created later, so the lock's own proven idle event starts the cover rather than a shared clock. A plugin cannot read another plugin, and the core already holds every effective setting. A global request covers both tiles of a Pro Display XDR, and a wake Hyprland performs works while the shell is down; a wake from sleep may never reach Hyprland as input, so it needs one owner that lights the panels. A watch that ignores inhibitors would let a playing video dim, blank and lock the screen; the window-event restart costs a later stage after an app opens or closes a window while the user is away.

**Rejected**: Omarchy's single idle monitor with timers for the later stages, because its reason, a screensaver window, does not exist in VGS. For equal times, a common deadline clock or recreating the lock's watch on a screensaver edit, because either would move the lock's deadline. A new `vgs.energy` plugin, because it needs `formerIds` ([D108](D108-renamed-plugin-declares-former-ids.md)) for one concern `vgs.power` already holds. Display off in `vgs.lock` or `vgs.displays`, because it is one session-wide compositor state with no per-panel backend. Watches that ignore inhibitors, a patched Hyprland, or an inhibitor reader of VGS's own to avoid the window-event restart.

**Revisit when**: Hyprland compares the inhibitor state before it resets idle notifications, the owner asks VGS to act on the window-event restart, a stage must draw a window, a stage must know another stage's state beyond the record, or a panel stays dark after a wake from sleep.
