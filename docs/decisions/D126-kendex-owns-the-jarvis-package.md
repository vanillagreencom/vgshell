# D126: Kendex owns the Jarvis package in every home

[← Decision Index](INDEX.md)

**Date**: 2026-11-06

**Status**: Active

**Research**: [VGS-2328](https://linear.app/vanillagreen/issue/VGS-2328/jarvis-plugin-depends-on-kendex-kendex-installs-and-updates-the-jarvis)

**Supersedes**: [D105](D105-jarvis-home-folder.md) only for the VGS-writer branch, its shipped render, ownership record and open-time layout or cleanup. D105's single knowledge home, instruction route and authority boundary remain active, including [D120](D120-satellite-forward-through-the-package.md)'s forwarding refinement.

**Decision**: Kendex is the only installer and updater of the Jarvis package in a Jarvis home. VGS depends on the kendex command and ships no Jarvis package copy. User-confirmed Setup creates a dedicated folder outside an existing project, initializes its Git repository, installs `vanillagreencom/kendex --bundle jarvis`, then invokes the package-owned initialization operation supplied by KEN-4957. VGS owns the choice and presentation, not a second home layout or installer. Opening a home and starting Voice install nothing. Arch uses the existing AUR route, with `kendex-bin` as the requirement's package and a matching hard dependency in the VGS recipes. Debian and Fedora use a confirmed requirement-install step for kendex's published architecture-matched `.deb` or `.rpm`; release assets alone do not satisfy a dependency from an apt or dnf repository. Add a hard dependency there only when the actual VGS install transaction can resolve it. Nix declares the upstream `kendex-cli` flake package after KEN-4954 lands. Before that, Setup may offer the upstream CLI-only installer, `curl -fsSL https://kendex.ai/install.sh | sh -s -- --cli-only`, only after confirmation; this is not a claim that the installer works on NixOS. Installer text is fixed data, never built from user text. On Setup open and at most once per day outside that explicit open, VGS consumes kendex's own home-scoped drift answer and offers one confirmed package update through kendex when that answer calls for refresh. Voice start performs no update check. Missing kendex and an unknown or pending comparison remain visible as such, never current. The user's instructions are the whole home `AGENTS.md`, not a `## Personality` section. The voice brain reads the persona's required guidance, including communication, through the safe help reader rather than a VGS-owned list; the persona loads once. Setup also offers a private clone of the main home for a second computer, arms that clone's home commit guards, sets its main host through `jarvis-session main-host --set`, then uses the existing secret-transfer route. It creates no second independent memory.

**Why**: The conditional writer left VGS homes on a frozen package without the package's complete skills, agents, hooks or session command. Giving kendex every package write removes that drift at its source. Its initializer gives standalone and VGS users one home contract. Its drift judge preserves held packages and distinguishes an update from an unread or unfinished comparison. A single whole-file instruction editor avoids a VGS-only section contract. The accepted cost is requiring kendex and user-confirmed setup, including app-plus-CLI native packages on Debian and Fedora. Release downloads are not package repositories. The unproved interim Nix installer cannot justify a support claim or a second VGS installer.

**Rejected**: Keep refreshing a VGS render, retain VGS-written homes beside kendex homes, or adopt them through a transition reader. Each keeps two package writers and the cause of the stale package. The owner states that no VGS-made home needs adoption. A version scanner or update check at each Voice start duplicates kendex's judge and puts package work on the conversation path.

**Revisit when**: Kendex stops supplying a usable home initialization, drift or package-install interface, a supported distribution cannot supply its command through the stated route, or a home must accept a package writer other than kendex.
