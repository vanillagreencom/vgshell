# D137: A capability provider reaches its declared plugin consumers

[← Decision Index](INDEX.md)

**Date**: 2026-11-17

**Status**: Active

**Research**: [VGS-2616](https://linear.app/vanillagreen/issue/VGS-2616), [VGS-2605 design review](https://linear.app/vanillagreen/issue/VGS-2605#comment-78adaf5c-0bdf-47e0-b166-2ef48ed0ad9f).

**Refines**: [D100](D100-validation-selects-by-inputs.md)'s static shell-load reach through the capability provider hub. [D117](D117-reuse-rows-on-recorded-passes.md)'s pass reuse is unchanged.

**Decision**: `smoke_loads_read` derives provider-to-capability edges from `Capabilities.qml`'s factory table, then capability-to-plugin edges from manifests judged by `PluginLogic.js` under node. A provider reaches the plugin source files whose manifests declare its capabilities, then the rows whose inputs name those files. These edges replace the provider's upward edge through `Capabilities.qml`; ordinary static loads, direct row inputs, core rows and row dependencies remain. A manifest-only catalog read does not observe every provider. An unreadable or unattributable provider mapping retains conservative reach. A shared harness input's top-level hunk, a helper every row uses, or unreadable reach still selects every row, because each row executes it or cannot be proved unaffected. A top-level hunk in another shared library keeps whole-file reach through its actual importers.

**Why**: Loading a provider while starting the shell does not mean a scene observes that provider. Core rows cover that startup. A plugin observes only the capabilities its manifest declares. `Capabilities.qml` exposes whole objects and passes provider functions as values, so function-only load narrowing cannot distinguish the consumers. This removes over-reach under validation's declared-input rule; a time target cannot justify omitting a reached row.

**Rejected**: Retaining every importer of `Capabilities.qml` as a consumer of every provider, or filtering the selected rows by their cost. The first confuses startup with observation; the second discards coverage. Narrowing top-level package-manager data through shared JavaScript is a separate policy change, because it has no provider-to-capability edge.

This record does not grant top-level data/member narrowing. VGS-2605's `scripts/smoke/harness.sh` selects all 138 listed rows today and after: its shared admission helpers run for every row. The today lists are source-derived at the design HEAD. Native `--list` on disposable copies of the implementation establishes the after lists without running scenes.

**Revisit when**: An unselected scene catches a provider regression, a plugin gains a supported way to observe an undeclared capability, or shared-library data changes require independently justified member-level reach.
